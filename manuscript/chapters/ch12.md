# 12장 자동 실행의 권한과 검증을 연결한다

상태: 초고 · 저자 검토 대기

## 능력의 증거와 행동의 허용을 나눈다

평가에서 좋은 결과를 낸 조합이라도 모든 업무의 실행 권한을 줄 근거가 생기는 것은 아니다. 같은 결과를 만드는 행동이 서로 다른 정보와 자원에 영향을 줄 수 있고, 환경이 바뀌면 확인한 조건도 달라질 수 있다. 리더는 무엇을 수행할 수 있는지와 무엇을 수행하도록 허용할지를 나누어 결정해야 한다.

P07 ‘독립된 검증’은 의도 소유자의 기준과 별도 자료·평가 경로로 수행자의 해석을 확인한다. P10 ‘범위가 정해진 자율성’은 영향과 복구 가능성에 맞춰 실행 권한·정지 조건·예외 경로를 정한다. 이 장은 두 관계를 실제 반영과 배포에 연결하는 운영 제안이다. 도구에 권한을 넣는 행위와 위임의 책임을 설계하는 일을 구분한다.

## 실행과 반영, 배포 권한을 따로 본다

자료를 읽고 초안을 만드는 일, 공유 결과를 수정하는 일, 사용 환경에 배포하는 일은 다른 영향을 가진다. 가상의 사내 문의 업무에서도 초안 저장과 답변 발송은 구분할 수 있다. 이는 설명 예시다. 검색이 정확했다는 증거가 외부 발송의 허용까지 대신하지 않는다.

각 단계에서 적용할 기준과 필요한 증거를 정한다. 코드나 문서의 검사뿐 아니라 권한의 범위와 대상, 기준의 버전을 확인한다. 수행자는 방법을 바꿀 수 있어도 결과를 받아들일 기준이나 정책의 경계를 임의로 낮출 수 없어야 한다. 기준 변경을 요청할 경로를 함께 제공한다.

저자의 병합 권한 분석은 반영 주체와 실제 검토 증거를 구분해 살핀다.[S44]

이 책은 계정이나 승인 표시만으로 판단의 범위와 품질을 확정하지 않는다. 어떤 자료와 기준으로 무엇을 수용했는지 남겨야 위임한 권한을 재검토할 수 있다.

| 권한의 대상 | 확인할 조건 | 다음 판단을 맡길 주체 |
|---|---|---|
| 읽기·분석 | 정보 범위·자료의 유효성 | 정보와 업무의 책임자 |
| 변경안 생성 | 허용 산출물·자원·검사 | 실행 계약의 책임자 |
| 공유 결과 반영 | 독립 판정·소비자 영향 | 결과 수용 권한자 |
| 배포·외부 행동 | 실제 환경·복구·사용자 약속 | 해당 위험과 운영의 책임자 |
| 경계 변경 | 새 영향·근거·회귀 평가 | 정책 변경 권한자 |

이 표는 권한 설계 제안이다. 여러 책임을 한 사람이 맡을 수 있지만 어떤 자격으로 무엇을 결정했는지 구분해야 한다. 모든 단계에 새 승인을 추가하자는 뜻은 아니다. 정한 조건 안에서 자동으로 처리할 범위를 명시한다.

전자동 개발을 허용할 범위에서는 정해진 조건의 충족이 다음 행동의 허용으로 이어져야 한다. 단계마다 같은 사람의 새 지시를 받는 구조는 자동 도구를 쓰더라도 정상 경로의 전자동 운영과는 구분한다. 자동 진행의 근거와 중단·이관 조건을 함께 정하고, 사람이 개입하지 않은 정상 실행도 어떤 정책과 증거로 진행됐는지 이력에 남긴다.

## 변경의 위험과 현재 증거를 병합 판단에 연결한다

데모의 [병합 판단 코드](https://github.com/roboco-io/the-software-factory-demo/blob/25a73b9c342ef380f96ff0d705df9b7ef33dd82c/packages/factory/src/stages/gate.ts)는 변경 파일과 필수 검사, 현재 커밋에 대한 리뷰 결과를 함께 읽는다. T1 변경에는 현재 커밋의 승인 판정을 요구하고, T2·T3 변경과 개선 PR은 자동 병합 대상에서 제외한다. T0에는 별도 조건이 적용된다.[S60] 여기서 T0부터 T3까지는 데모가 정의한 위험 등급이며 모든 조직의 표준은 아니다.

리더는 위험 등급별로 필요한 증거와 누가 반영할 수 있는지 설명할 수 있어야 한다. 옛 버전의 승인을 새 변경에 사용하지 않는 조건도 필요하다. 코드가 자동 병합을 거부하는 것과 사람이 하는 모든 병합에 동일 승인이 강제되는 것은 다르다. 데모 문서는 유일한 코드 소유자가 직접 작성한 변경에서 승인 강제가 제한되는 경우를 밝힌다.[S59] 조직에서 적용할 때에는 역할 배치와 실제 저장소 권한을 함께 확인한다.

## 검증을 권한 밖에서 유지할 조건을 정한다

[7장](ch07.md)은 기준·자료·판정 경로의 독립성을 다뤘다. 이 장은 그 경로를 실제 권한으로 유지하는 문제를 다룬다. 누가 검사 장치와 평가 자료를 바꿀 수 있고, 누가 그 변경의 충분성을 판단하며, 누가 결과를 반영할 수 있는지 함께 확인한다. 실행 권한을 준 뒤 이 구분이 사라진다면 앞서 얻은 평가 증거만으로 반영을 허용하기 어렵다.

검사를 실행하지 못한 경우, 오래된 증거를 읽은 경우, 정상 결과를 잘못 거부한 경우를 나눈다. 부족한 증거는 통과로 바꾸지 않고 해당 위험의 책임자에게 넘긴다. 반복 업무의 자동 판정과 예외 판단을 배치하되, 판정 경로가 미리 알지 못하도록 숨겨 둔 실패 사례와 정상 결과로 그 경로가 실제로 작동하는지 확인한다. 운영에서 놓친 사건과 판정 대기를 함께 보며 권한을 유지할 범위를 재검토한다.

## 하네스의 허용 판단을 실제 실행 경계와 맞춘다

모델에게 허용 범위를 설명하는 일은 행동의 경계를 실제로 집행하는 일과 함께 이루어져야 한다. 하네스는 도구 호출 전에 작업의 권한과 대상을 확인하고, 실행 환경은 그 범위의 자격 증명과 자원만 제공하도록 구성한다. 정책 책임자가 정한 경계와 하네스의 판정, 실제 도구의 접근 범위가 일치하는지 확인한다.

하네스에 호출 전 검사가 있어도 다른 도구나 경로로 같은 행동을 할 수 있다면 경계가 유지되지 않을 수 있다. 중단·권한 회수 뒤 이미 진행 중인 행동이 어떻게 처리되는지도 살핀다. 허용 여부를 확인할 수 없는 상태를 자동 승인으로 바꾸지 않고, 부족한 증거와 진행 상태를 판단 책임자에게 돌려보낸다. 하네스 운영자에게 집행을 맡겨도 정책 예외와 결과 수용의 사업 책임은 해당 권한자에게 남는다.

## 제한된 반영에서 운영 증거를 얻는다

위임 책임자는 허용한 행동·대상·수행 주체·기간과 재평가 조건을 함께 남긴다. 모델이나 실행 환경, 책임자가 바뀌었다면 기존 증거와 권한을 그대로 이어도 되는지 확인한다. 갱신 판단을 받지 못한 권한이 자동으로 확대되거나 예외 권한이 정상 권한으로 남지 않도록 종료 상태도 점검한다. 읽기 권한을 유지할 수 있어도 공유 결과의 반영이나 외부 발송은 다시 판단해야 할 수 있다.

테스트 환경과 실제 사용 환경은 다를 수 있다. 이 책은 확인한 범위 안에서 반영 대상을 제한하고 운영 관찰과 중단 조건을 연결하도록 제안한다. 작은 사용자 집단이나 내부 업무에서 시작할 수 있지만, 그 범위가 다른 소비자와 데이터에 미칠 영향도 확인해야 한다.

단계적으로 넓힐 때에는 어떤 조건을 새로 확인할지 정한다. 초기 결과가 정상이라는 이유로 더 큰 권한을 자동으로 부여하지 않는다. 대상과 부하, 데이터와 사용 조건이 달라지면 기존 증거가 충분한지 다시 판단한다. 제한된 반영이 안전하다는 명칭만으로 실패 영향이 제한되는 것은 아니다.

중단할 장치와 책임도 실행 전에 확인한다. 누가 어떤 신호로 권한을 회수하고 진행 중인 행동을 어떻게 처리할지 정한다. 정지 요청이 실제로 적용되는지, 넓은 권한이나 예외가 종료 뒤 남지 않는지 확인한다. 8장의 중단·복구·재개 기준을 이 권한 구조에 연결한다.

## 예외가 정상 경로를 지우지 않게 한다

예외에는 대상 작업·허용 행동·이유·책임자·종료 조건이 필요하다. 문제가 생겼다는 이유로 검증 전체를 끄면 어떤 조건을 포기했는지 알기 어렵다. 긴급 복구에서는 영향을 줄이는 판단이 먼저일 수 있지만 포기한 확인과 후속 재검증을 남겨야 한다.

예외가 반복되면 원인을 조사한다. 정책이 현실을 빠뜨렸는지, 수행 능력이 부족한지, 판정 장치가 같은 정상 결과를 막는지 구분한다. 예외 횟수가 줄었어도 중요한 사건을 놓쳤거나 보고가 사라졌다면 개선이라고 판단하기 어렵다. 허용 범위와 실제 집행의 차이를 확인해야 한다.

## 리더는 권한과 결과의 연결을 재검토한다

P07은 숨겨 둔 실패 사례의 발견과 오류 상관관계를 확인한다. P10은 허용 범위 밖 실행과 정지 조건의 작동을 본다. 배포 뒤 결함과 복구, 예외 대기와 판정 부담을 함께 기록한다. 평가에서의 적격성과 운영에서의 권한 유지 여부를 같은 추적 자료로 연결한다.

원서의 품질·자동 테스트·반복 전달이라는 주제와의 연결은 기존 공개 목차 범위다. 다음 장은 실행 조합을 구매·운영하는 능력과 인간의 판단 역량에 어떤 투자를 할지 다룬다.
