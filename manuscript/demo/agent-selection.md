# 에이전트 선택과 평가

검토 역할의 이름을 붙이는 일과 실제로 다른 실행 조합을 사용하는 일은 다르다. 데모에서는 역할 설정, 배정 코드, 실제 호출 단계가 연결된다.[S104]

## 선언·배정·호출을 함께 읽는다

설정은 구현과 검토 등의 역할에 사용할 도구와 예산을 선언한다. 배정 코드는 모델 설정을 읽고, 검토에는 구현과 다른 실행 도구를 선택하려 한다. 다른 도구를 배정할 수 없으면 오류로 처리한다. 수행 계획은 이 선택과 예산을 다음 실행에 전달한다.[S104]

검토 단계는 변경 제안의 메타데이터에서 구현 도구를 확인해 검토 조합을 고르고, 선택에 실패하면 사람에게 넘긴다. 읽기 전용 요청과 검토 예산도 호출에 전달한다. 설정 파일의 선언만 보는 대신 실제 호출까지 이어지는지 확인하는 이유다.[S104]

## 리더의 판단과 한계

다른 도구를 사용한다는 조건이 서로 다른 오류를 발견한다는 효과를 보장하지 않는다. 업무에서 숨겨 둔 실패 사례와 비용·지연·불필요한 거부를 함께 관찰해야 한다. 데모의 특정 모델·예산 기본값을 조직의 추천값으로 가져오지 않는다. 읽기 전용 요청도 전체 환경의 강제성을 검증한 결과와 구분한다.

2026년 10월 15일 확인한 고정 버전의 문서와 코드 구조를 설명한다. 데모를 직접 실행하거나 실제 조직의 효과를 검증한 결과는 아니다. 정확한 판본과 확인 범위는 출처에서 추적할 수 있다.
