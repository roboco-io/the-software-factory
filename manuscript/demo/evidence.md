# 결과를 판단하는 증거

검사가 실패했다는 사실만으로 버그를 재현했다고 말할 수는 없다. 데모의 수정 증거 판정은 ‘수정이 없을 때 실패하고 수정한 뒤에는 통과하는가’를 같은 테스트로 비교한다.[S101]

## 두 버전과 실패의 종류를 연결한다

대상 분류는 팩토리 봇의 버그 수정 제안인지 확인한다. 대상이면 추가·수정한 테스트를 수정 전 코드에 적용하고 수정 후 코드에서도 같은 테스트를 확인한다. 수정 전 개별 검사 조건의 실패와 수정 후 통과가 필요하다. 검사 수집 오류·시간 초과·보고서 누락은 버그를 재현한 증거가 아니다.[S101]

이 흐름은 대상 판정, 두 버전의 실행, 결과 보고서 해석이 연결되어야 성립한다. 비대상 변경은 이 비교를 수행하지 않고 통과할 수 있고, 브라우저 전체 동작 검사는 이 판정의 범위 밖이다. 통과 표시 하나에서 모든 변경에 같은 수준의 증거가 있다고 추론하지 않는다.[S101]

| 관측한 상태 | 수정 증거로 읽을 수 있는가 |
|---|---|
| 수정 전 해당 테스트의 검사 조건 실패, 수정 후 같은 테스트 통과 | 대상 변경이라면 정의한 수정 증거를 충족하는지 판정한다. |
| 테스트 수집 오류·시간 초과·보고서 누락 | 원하는 결함이 재현된 증거로 처리하지 않는다. |
| 비대상 변경의 통과 | 수정 전후 비교를 수행했다는 뜻이 아니다. |

표는 이 판본의 판정 의미를 요약한 것이며 새로 실행한 테스트 결과가 아니다.

## 리더의 판단과 한계

업무에서 주장하는 실패를 어떤 관측으로 확인할지 먼저 정하고, 검사 불능을 유효한 증거로 처리하지 않아야 한다. 데모는 악의적인 변경 작성자를 막는 보안 장치가 아니다. 운영 안내는 테스트 코드가 같은 환경의 결과 보고서를 조작할 수 있음을 명시한다.[S101] 업무에 필요한 독립성·검사 범위·수용 책임은 별도로 설계한다.

2026년 10월 15일 확인한 고정 버전의 문서와 코드 구조를 설명한다. 데모를 직접 실행하거나 실제 조직의 효과를 검증한 결과는 아니다. 정확한 판본과 확인 범위는 출처에서 추적할 수 있다. 테스트 정의를 읽었다는 사실과 테스트를 직접 실행해 통과를 확인한 사실도 구분한다.
