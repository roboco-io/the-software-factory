# 결과를 판단하는 증거

새 플랫폼의 리뷰 의견과 저장소 검사 결과는 서로 다른 증거다. 리뷰 샌드박스는 코드를 읽고 구조화된 판정을 내며, 제어 평면은 그 판정과 현재 커밋의 필수 체크를 따로 확인한다.[S160]

## 두 버전과 실패의 종류를 연결한다

리뷰는 새 샌드박스에서 지정한 PR 커밋을 대상으로 한다. 읽기 전용 도구로 실행하도록 요청하고, 외부 이슈와 diff를 지침과 구분한다. 검토 결과가 요구한 형식에 맞지 않거나 승인과 중대한 지적이 충돌하면 유효한 승인으로 읽지 않는다.[S160]

리뷰한 커밋과 반영 직전 커밋의 일치를 확인하는 일은 수정 전 실패·수정 후 통과를 시험하는 일과 다르다. 현재 플랫폼이 모든 변경에 과거 구현의 재현 검사 방식을 자동 적용한다고 쓰지 않는다. 어떤 실행 증거가 필요한지는 관리 대상 저장소의 체크와 계약에 연결한다.

| 얻은 자료 | 확인할 수 있는 범위 |
|---|---|
| 구조화된 리뷰 | 코드상 판정과 지적의 정의된 형식 |
| 현재 커밋의 필수 체크 | 그 검사 경로가 보고한 실행 결과 |
| 운영 관찰 | 배포 이후 사용자 결과와 남은 결함 |

앞의 둘이 맞아도 마지막 질문까지 끝나는 것은 아니다. 리뷰 결과 누락을 지적 0건으로 취급하거나, 병합을 실제 사용자 문제 해결로 보고하지 않는다.

## 리더의 판단과 한계

다른 모델·새 샌드박스라는 구분만으로 독립성이 완성되지는 않는다. 공유한 요구 누락과 검증 자료의 한계를 살펴야 한다. 읽기 도구 설정과 실제 환경의 강제성을 구분하며, 이 책은 실행 시험으로 이를 보장하지 않았다.

2026년 11월 9일 확인한 리뉴얼 플랫폼의 고정 판본을 기준으로 썼다. 문서·코드의 정적 구조를 확인했으며, 에이전트 실행·로그인·병합을 직접 시험하거나 운영 효과를 검증한 결과는 아니다.
