# 관찰을 개선으로 연결하기

실행 기록과 자동 자기개선은 다른 단계다. 새 플랫폼은 상태·사유 코드·비용을 관찰할 기반을 제공하지만, 확인한 구현에서 이전의 개선 후보 수집·규칙 수정 PR·평가 루프를 그대로 찾을 수는 없다.[S165]

## 후보에서 평가까지

현재 포털의 실패·대기 이유와 실행 사건은 사람이 바꿀 대상을 조사하는 근거가 된다. 이 자료를 다음 요구와 회귀 과제로 연결하는 것은 책이 제안하는 운영이다. 플랫폼이 이미 원인을 확정하고 정책·하네스를 자동으로 수정한다는 구현 사실로 쓰지 않는다.[S165]

필요한 작업을 이번 계획에서 빠뜨렸는지, 반복 계획 수립의 입력이 부족했는지, 명확한 정책의 집행이 실패했는지 나눈다. 관찰된 증상만으로 프롬프트를 늘리거나 판정 기준을 낮추지 않는다. 변경 권한을 확인하고 같은 실패와 정상 조건으로 효과를 다시 검토한다.

[4장의 두 개선 루프](../chapters/ch04.md#fig-4-1)는 이 판단을 의도와 하네스의 변경으로 나누는 책의 제안이다. 운영자가 기록을 보고 다음 행동을 선택할 수 있다는 것과 개선 루프 전체를 자동화했다는 것은 다른 확인 상태다.

## 과거 실행 기록은 별도로 읽는다

2026년 10월 12일의 개선 PR #47과 검증 PR #48은 **이전 구현인 Conveyor의 역사 사례**다. 당시에는 이전 규칙의 미검출과 새 규칙의 검출을 비교했고, #47은 병합됐으며 #48은 병합 없이 닫혔다.[S68] 새 플랫폼에서 다시 실행한 결과가 아니다.

[당시 개선·평가 코드](https://github.com/roboco-io/conveyor/blob/5b1927f8328266070c3d0bf98bac194dc21df012/packages/factory/src/stages/eval.ts)와 [이전 운영 안내](https://github.com/roboco-io/conveyor/blob/5b1927f8328266070c3d0bf98bac194dc21df012/docs/operations.md)는 그 판본의 확인 범위를 읽기 위한 자료다.[S106] 과거 [개선 평가 기록](https://github.com/roboco-io/conveyor/actions/runs/38223377457/job/114724977130)과 [검증 기록](https://github.com/roboco-io/conveyor/actions/runs/38223958193/job/114726765443)도 당시 조건으로 구분한다. 이 과거 결과를 현재 플랫폼의 자동 자기개선이나 자연 발생 실패 감소의 증거로 사용하지 않는다.

## 리더의 판단과 한계

자기개선의 목표를 새 플랫폼의 완성된 기능으로 소급하지 않는다. 정책 안의 자동 개선을 허용하려면 변경 대상·별도 평가·실제 권한·복구 조건을 갖춰야 한다. 현재의 관찰 자료만으로 운영 결함의 장기 감소를 주장하지 않는다.

2026년 11월 9일 확인한 리뉴얼 플랫폼의 고정 판본을 기준으로 썼다. 문서·코드의 정적 구조를 확인했으며, 에이전트 실행·로그인·병합을 직접 시험하거나 운영 효과를 검증한 결과는 아니다.
