# 활동과 성과를 구분하는 지표

완주율을 이해하려면 성공 횟수보다 먼저 분모와 관찰 기간을 알아야 한다. 데모의 주간 보고는 실행 기록을 고른 뒤 완료율·실패·알려진 비용을 계산한다.[S105]

## 기록에서 숫자가 만들어지는 경로

주간 처리 단계는 최근 7일의 기록을 계산에 넘긴다. 완주율의 분모는 그 기간에 구현 실행 기록이 있는 요청이다. 배포 성공 기록이 있고 그 기간의 모든 실행이 성공으로 남은 요청을 완주로 센다. 따라서 정책에 따라 사람에게 넘긴 경우도 완주에서는 제외될 수 있다.[S105]

알려진 비용만 합산하면서 비용을 보고한 기록 수도 함께 남긴다. 작은 표본은 데이터 부족으로 표시한다. 이 숫자는 기록된 범위의 결과이며, 보고되지 않은 비용이나 관찰 기간 밖의 작업을 자동으로 채우지 않는다.[S105]

[17장의 분모 그림](../chapters/ch17.md#fig-17-1)은 책이 제안하는 전체 요청과 자동 처리 범위의 구분이다. 이 데모의 분모는 기간 안에 구현 실행 기록이 있는 요청이므로 그림의 전체 요청 집합과 같다고 볼 수 없다. 집계에 들어오기 전 보류된 요청과 비용 미보고도 따로 살펴야 한다.

## 리더의 판단과 한계

기간 경계에서 한 요청의 구현과 배포가 나뉠 수 있다. 사람 이관이 올바른 정책 준수였는지와 결과를 자동 완주했는지는 다른 질문이다. 데모의 완주율을 사용자 성과나 인과적인 생산성 증가로 바꾸어 읽지 않는다. 인간의 확인 시간·재작업·전체 비용은 조직의 판단에 맞게 별도로 수집해야 한다.

2026년 10월 15일 확인한 고정 버전의 문서와 코드 구조를 설명한다. 데모를 직접 실행하거나 실제 조직의 효과를 검증한 결과는 아니다. 정확한 판본과 확인 범위는 출처에서 추적할 수 있다. 이 페이지가 대시보드의 모든 계산과 실시간 데이터 품질을 검증한 것은 아니다.
