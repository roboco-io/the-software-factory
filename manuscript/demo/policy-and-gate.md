# 정책과 수용 경계

같은 에이전트가 만든 변경이라도 문서 수정과 인증 기능 수정의 위험은 다르다. 데모는 바뀐 파일의 위험을 분류하고 그 결과를 자동 병합 또는 사람의 판단 경로와 연결한다.[S100]

## 분류에서 반영 판단까지

위험 정책은 변경 경로별 등급과 필요한 검사 항목을 선언한다. 분류 코드는 파일별 규칙을 적용하고 변경 전체에서 가장 높은 위험을 사용한다. 병합 판단은 그 위험과 현재 변경 버전의 검사·리뷰를 함께 읽는다. 낮은 위험 일부는 자동 처리하지만 높은 위험과 개선 변경은 사람에게 넘긴다.[S100]

검토 승인을 받은 뒤 코드가 바뀌면 예전 승인을 그대로 쓰지 않도록 현재 버전과 판정을 연결한다. 이 연결은 검토한 대상과 실제 반영할 대상을 맞추기 위한 장치다. 파일 목록이나 위험을 확정할 수 없는 경우도 자동 반영에서 막는다.[S100]

## 리더의 판단과 한계

T0부터 T3까지는 이 데모의 **변경 위험 등급**이다. 책의 최상위 원칙·조직·제품·작업별 **정책 적용 범위**와 다른 구분이다. 데모의 등급을 조직의 표준으로 그대로 가져오거나 정책 계층 전체가 구현됐다고 해석하지 않는다.

코드의 자동 병합 거부와 모든 사용자의 직접 병합을 막는 저장소 권한은 별도로 확인해야 한다. 운영 안내는 작성자가 유일한 코드 소유자일 때 승인 강제가 제한되는 경우를 밝힌다. 또한 이 병합 판정은 일부 생략·중립 검사 상태도 통과로 다루므로, 허용된 상태와 검사 실제 수행을 구분해야 한다.[S100]

2026년 10월 15일 확인한 고정 버전의 문서와 코드 구조를 설명한다. 데모를 직접 실행하거나 실제 조직의 효과를 검증한 결과는 아니다. 정확한 판본과 확인 범위는 출처에서 추적할 수 있다.
