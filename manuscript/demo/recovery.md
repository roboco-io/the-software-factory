# 실패에서 복구로

새로운 일을 잠시 멈추는 조치와 진행 중인 일을 취소하는 조치, 이미 생긴 결과를 복구하는 조치는 서로 다르다. 데모는 전체 실행 기록을 보는 차단기와 개별 요청을 다루는 명령·상태 전이를 나눈다.[S102]

## 무엇을 멈추고 무엇을 재개하는가

차단기는 관찰 기간과 최소 표본 조건 아래 구현·수정 실행의 실패 비율을 판단한다. 조건을 넘으면 새 구현 시작을 일시 중지한다. 한편 개별 중단 명령은 권한과 현재 상태를 확인하고 관련 실행 취소와 사람 이관을 처리한다. 전체 차단 해제와 개별 요청의 재시도는 같은 동작이 아니다.[S102]

실행 취소가 앞서 수행한 외부 변경까지 되돌리는 것은 아니다. 준비 단계에서 실패해 진행 중 상태에 남은 요청은 사람이 상태를 바꾼 뒤 재시도해야 하는 경우가 있다. 차단기가 이런 작업을 모두 자동 복구한다고 가정하지 않는다.[S102]

| 조치 | 직접 다루는 범위 | 같은 것으로 볼 수 없는 것 |
|---|---|---|
| 실패율 차단기 | 조건을 충족할 때 새 구현 시작을 일시 중지 | 진행 중 작업의 일괄 취소·개별 복구 |
| 개별 중단 명령 | 권한·상태를 확인한 실행 취소와 사람 이관 | 이미 발생한 외부 효과의 되돌리기 |
| 재개·복구 판단 | 현재 상태와 남은 영향을 확인해 다음 행동 선택 | 차단 해제만으로 모든 요청의 복구 완료 선언 |

## 리더의 판단과 한계

무엇을 중단해도 되는지, 계속해야 하는 확인과 기록은 무엇인지 정한다. 재개 판단에는 원인·남은 외부 효과·새 시도의 조건이 필요하다. 데모의 표본·임계값은 특정 구현의 선택이며 모든 조직에 적절한 수치로 검증된 것이 아니다. 중단 요청의 정의만으로 외부 효과가 복구됐다고 보고하지 않는다.

2026년 10월 15일 확인한 고정 버전의 문서와 코드 구조를 설명한다. 데모를 직접 실행하거나 실제 조직의 효과를 검증한 결과는 아니다. 정확한 판본과 확인 범위는 출처에서 추적할 수 있다.
