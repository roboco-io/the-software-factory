# 요청에서 실행 가능한 작업까지

요청을 보기 좋게 정리한 결과가 곧 작업을 시작할 권한은 아니다. 데모는 목표·수용 기준을 입력받고, 에이전트의 정리와 권한자의 시작 판단을 구분한다.[S99]

## 요청과 승인을 잇는 흐름

기능 요청서는 달성할 목표와 받아들일 조건을 받는다. 정리 역할의 에이전트는 파일을 바꾸지 않고 요청 종류·예상 위험·수용 기준·요약을 구조화한다. 프로그램은 결과의 형태를 검사해 댓글과 라벨로 남긴다. 이 형식 검사는 사업 목표가 적절한지까지 판단하지 않는다.[S99]

작업 시작 명령은 저장소의 쓰기 권한과 요청 상태를 확인한다. 상태 전이는 정리 작업과 실행 승인을 구분한다. 다만 코드에는 새 요청에서 승인 상태로 바로 넘어가는 경로도 있어, 모든 요청에 에이전트 정리가 반드시 선행한다고 읽어서는 안 된다.[S99]

## 리더의 판단과 한계

예상 위험은 요청 단계의 판단이다. 실제로 변경된 파일의 위험 판정과 같은 것으로 취급하지 않는다. 정리 결과에 빠진 조건을 누가 보완하고, 누가 자원 사용과 실행을 허용할지 정해야 한다. 이번 확인은 지침·코드의 정의이며 모든 환경에서 읽기 전용 제약이 강제됨을 검증한 것은 아니다.

2026년 10월 15일 확인한 고정 버전의 문서와 코드 구조를 설명한다. 데모를 직접 실행하거나 실제 조직의 효과를 검증한 결과는 아니다. 정확한 판본과 확인 범위는 출처에서 추적할 수 있다.
