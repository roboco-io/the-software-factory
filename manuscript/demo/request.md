# 요청에서 실행 가능한 작업까지

요청을 접수하는 일과 실행 권한을 주는 일은 다르다. 리뉴얼 플랫폼에서 운영 중인 경로는 등록된 저장소의 이슈에 운영자가 실행 라벨을 붙인 요청을 선별한다. 이전 예제의 AI 트리아지·댓글 정리 흐름을 그대로 사용하는 구조는 아니다.[S158]

## 요청과 승인을 잇는 흐름

웹훅 처리기는 서명과 이벤트 종류, 실행 라벨, 운영자의 숫자 ID, 허용된 저장소와 열린 이슈인지 확인하고, 운영자가 팩토리 전체를 멈춘 상태가 아닌지도 확인한다. 이슈의 요구사항은 수행할 입력이며 제어 평면의 권한이나 지침을 바꿀 허가가 아니다. 모델에 전달하는 프롬프트도 이슈 내용을 외부 입력으로 구분한다.[S158]

이슈별 상태 기계는 중복 전달과 이미 끝난 실행을 구분하고, 예산·동시 실행 조건을 확인해 작업을 시작한다. 입력을 받았다는 사실과 실제 실행을 시작했다는 상태를 분리해 읽어야 한다.

이 흐름에는 저장소·이슈·기준 코드와 공통 실행 절차가 연결된다. 책의 실행계획은 그 안에서 이번 작업에 선택할 순서·의존성·확인 방법이다. 요청 데이터나 상태 기계를 그 계획 자체와 동일시하지 않는다. 복잡한 요구의 계획 품질과 사업적 적절성은 별도로 확인할 과제다.

## 게스트 요청 심사는 코드로만 있고 접수는 닫혀 있다

2026년 11월 17일의 플랫폼 판본에는 운영자가 아닌 사람이 연 이슈를 다루는 별도 경로가 추가돼 있다. 이 경로는 설정에 지정한 저장소에서만 동작한다. 작성자가 사람이며 운영자가 아니고, 게스트용 템플릿이 붙이는 라벨이 있는 새 이슈만 심사 대상이다. 프로그램이 계정의 가입 기간과 계정별·저장소별 하루 한도를 먼저 검사하고, 통과한 요청만 심사 모델이 저장소의 게스트 정책 파일에 적힌 조항 코드를 써서 인용·각하·관리자 판단 가운데 하나로 판정한다. 모델의 답이 정해진 형식과 조항에 맞지 않으면 인용으로 처리하지 않고 관리자 판단으로 넘긴다. 인용된 요청만 실행을 시작하며, 관리자 판단으로 넘어간 요청은 운영자가 기존의 실행 라벨을 붙여야 시작한다.[S158]

이 경로는 이 책이 운영 사례로 쓸 수 있는 상태가 아니다. 후보 판본의 설정에서 게스트를 받을 저장소 목록은 비어 있다. 플랫폼의 기록에 따르면 2026년 11월 15일에 Conveyor를 이 목록에 넣어 접수를 열었으나, 실제 게스트 요청으로 심사가 동작하는 것을 확인하지 못한 상태였으므로 11월 17일에 다시 빼서 접수를 닫았다. 같은 기록은 모델 호출과 GitHub 작업을 가짜 서비스로만 시험했고, 실제 게스트 요청은 처리된 적이 없다고 적는다. 이 책도 실제 요청을 처리한 기록을 확인하지 못했다. 이 구현은 플랫폼 쪽에서 아직 진행 중인 단계이므로 구조가 바뀔 수 있다.

## 리더의 판단과 한계

운영자가 시작을 허용하는 것은 현재 운영 중인 데모 경로의 선택이다. 책의 일반 원칙은 필요한 정책·증거·권한 조건을 갖춘 범위의 시작 판단도 자동화할 수 있다는 것이다. 모델이 요청을 심사해 시작 여부를 정하는 경로가 코드에 있다는 사실은 이 원칙이 검증됐다는 뜻이 아니다. 그 경로는 실제 게스트 요청을 처리한 적이 없고 접수도 닫혀 있다. 운영자 허용만으로 요청의 완전성이나 목표 달성을 보장하지 않는다.

2026년 11월 17일의 플랫폼 커밋(2026년 11월 19일 확인)을 기준으로 썼다. 문서·코드의 정적 구조를 확인했으며, 에이전트 실행·로그인·병합을 직접 시험하거나 운영 효과를 검증한 결과는 아니다. 게스트 요청과 관련해 ‘플랫폼의 기록’이라고 쓴 부분은 플랫폼 저장소가 스스로 적은 내용이며 이 책이 재현한 것이 아니다.
