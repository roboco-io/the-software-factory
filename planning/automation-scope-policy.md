# 원칙·정책에 따른 완전 자동화 — 집필·검토 기준

- 결정일: 2026-10-15. 저자가 사람의 승인 없는 완전 자동화를 목표에서 제외하던 기준을 수정하고 책 전체에 적용하도록 지시했다. 현재 원고에 이미 있는 자동 수용 설명도 이 기준으로 통합한다.
- 지위: 저자가 정한 책의 설계 원칙이다. 특정 제품이 이미 이 수준을 달성했다는 관측 사실이나 모든 업무의 성공 보장이 아니다.

## 현재 기준

**원칙과 정책이 허용하고 필요한 수행·검증·권한·복구 조건을 갖춘 범위는 개별 실행에 대한 사람의 승인 없이 끝까지 자동화한다. 사람의 판단이 필요한 범위와 아직 조건을 확인하지 못한 범위는 정책으로 구분한다.**

완전 자동화의 대상은 구현만이 아니다. 범위에 포함한 요청 접수·실행 허용 판단·분해·수행·검증·수용·반영·배포와 운영 관찰, 정책이 처리 방법과 한도를 정한 예외·재시도·복구까지 연결한다. 의도와 정책에 따른 범위 분류도 자동으로 수행할 수 있다. 어떤 구간을 평가했는지 명시한다.

사람이 의도·원칙·정책과 위임 범위를 정하는 일, 그 결과에 책임지는 일과 개별 실행을 승인하는 일은 구분한다. 책임자가 있다는 이유로 자동 범위에 승인 단계를 남기지 않는다. 사람의 오너십이나 학습을 위해 불필요한 실행 승인을 만들지 않는다.

## SDLC 전반의 보안 내재화

보안 통제는 자동화가 따라야 할 설계 요건이며 요구·설계·구현·검증·배포·운영·종료에 걸쳐 집행한다. 단계별 필수 통제와 증거·책임이 확인된 범위에서 실행하고, 확인하지 못한 경로는 허용 범위를 제한하거나 보류한다. 이 조건은 모든 개별 실행을 사람에게 승인받으라는 뜻이 아니며 기존 자동 처리·사람 판단·조건 미확인의 구분을 유지한다.

## 범위 판단

- 상위 원칙에 위배되지 않고 적용 정책이 행동·대상·입력·자원·종료 조건을 허용하는가.
- 수행과 독립 판정을 포함해 요구한 증거를 확보·평가할 수 있고 결과의 실제 상태를 확인할 수 있는가.
- 실행 환경의 권한, 중단, 영향 제한, 필요한 복구 경로가 확인되었는가.
- 조건 변화·증거 누락·범위 밖 입력을 탐지하고 자동 보완·보류·이관의 경로를 집행할 수 있는가.
- 적용되는 규정·계약·조직 원칙이 해당 판단을 사람에게 유보하는가.

위 조건과 증거를 충족한 범위는 완전 자동화를 목표로 한다. 위험이 크다는 이유만으로 일률적으로 사람 승인 대상으로 고정하지 않는다. 위험이 크면 필요한 증거·통제·복구 조건을 더 엄격히 평가하며, 실제로 충족하지 못하면 자동 범위에 넣지 않는다.

사람에게 유보된 판단이나 현재 정책으로 해결하지 못하는 약속·경계 변경은 해당 책임자에게 넘긴다. 판단 불능·금지·권한 부족은 자동 승인으로 처리하지 않는다. 중단 뒤에도 정책이 허용한 상태 확인과 영향 제한·복구는 자동으로 수행할 수 있다. 이를 사람의 승인으로 원칙을 위반해도 된다는 뜻으로 쓰지 않는다.

정상/예외라는 사건 이름과 자동/사람이라는 처리 주체는 같은 구분이 아니다. 정의된 예외도 자동 처리할 수 있고 정상처럼 보이는 결과도 정책이 정한 인간 판단 조건에 해당할 수 있다.

정책은 자연언어 지침·구조화된 규칙 또는 둘의 결합으로 표현할 수 있다. 형식 자체는 집행이나 결정론을 보장하지 않는다. 규칙·평가기·입력과 오류 처리의 의미를 연결하고, 모델의 해석 결과와 실제 상태의 신뢰성을 따로 평가한다. 표현 형식이 아니라 원칙·적용 범위·변경 권한으로 우선순위를 정한다.

사람 확인 필요 여부의 분류와 해당 작업의 최종 결정도 구분한다. 권한 설정 변경을 사람 확인 대상으로 정한 정책은 변경 여부를 명시적 규칙으로 판정해 이관할 수 있다. 비용·품질·응답 시간 사이의 트레이드오프는 LLM이 위임 범위와 문맥을 해석해 이관 필요성을 분류할 수 있다. 모델이 명시적 사람 확인 의무를 해제하거나 유보된 결정을 대신 승인하지 못한다. 기존 위임 범위와 증거를 충족한 비용 선택은 자동 처리할 수 있으며, 판단 근거가 부족하면 보류한다. 이는 저자의 설명 예시이며 실제 조직의 운영 관측이 아니다.

회복 가능성은 대상과 사안·영향·위임·증거와 함께 판단한다. 단방향 결정에 사람의 개별 승인을 일괄 요구하거나 양방향 결정에 자동 실행을 일괄 허용하지 않는다. 비가역 효과를 허용하는 정책은 그 사실을 전제로 허용 대상·영향 한도·사전 판정·실행 중단 가능 시점·중복 방지·사후 확인을 구체화한다. 복구 조건을 갖춘다는 표현은 모든 행동을 반드시 원상 복구할 수 있어야 한다는 뜻이 아니다. 필요한 경우의 복구와 회복할 수 없는 효과의 허용 조건을 명시한다. 조건 미확인은 보류하며 기존 원칙을 우회하지 않는다.

보안은 상위 정보 보호 경계로 엄격히 적용한다. 권한 설정을 원복할 수 있어도 불필요한 접근으로 허용 범위 밖에 전달된 정보의 회수를 보장할 수 없으므로 양방향 변경으로 일괄 분류하지 않는다. 작업에 필요한 대상·행동·기간과 전달 경계를 실행 전에 제한하며, 권한 회수를 노출 이전 상태의 회복으로 계산하지 않는다. 단방향의 조건부 자동화는 이런 보안 원칙을 우회할 허가가 아니다. 사람의 승인도 원칙 위반을 정당화하지 못한다.

## 원고·사례·검증에 적용

1. 1장·서문은 승인 없는 완전 자동화를 정책으로 정한 범위의 목표로 명시한다. 3장은 분류 기준, 7·8·12장은 수용·예외·실제 집행, 17·18·20장은 측정·도입·확대에 연결한다.
2. P11의 ID·이름·개입을 필요한 예외에 모으는 목적은 유지한다. 정상 결과 외의 모든 예외·큰 영향을 사람에게 넘기는 식의 정의는 고친다. 다른 패턴도 판정자·보고 수신자를 사람으로 고정하지 않는다.
3. 데모와 외부 사례의 실제 승인 단계·제약·원문 인용은 보존한다. 현재 구현의 선택을 팩토리의 필수 조건으로 일반화하지 않는다. 과거 블로그·검토·결정 기록은 당시 맥락으로 유지한다.
4. 자동화 허용 범위의 비율과 그 범위의 무승인 완주를 나누어 측정한다. 사람 판단이 지정된 업무, 증거 부족으로 보류된 업무와 예상 밖 개입도 따로 남긴다. 자동화 대상의 분모를 줄여 성과를 부풀리지 않는다.
5. 정책 변경·유지와 표본 점검·학습의 비용도 기록한다. 개별 실행 승인을 없애도 원칙·정책의 관리와 결과 책임이 사라지지는 않는다. 하위 정책과 실행계획의 자동 개선도 미리 정한 변경 권한과 별도 검증 안에서 허용한다.

이 문서는 책의 내용 기준이다. 이번 대화의 작업 권한이나 저장소의 리뷰·게시 절차를 자동으로 바꾸지 않는다. 실제 정책의 승인·외부 시스템 변경·공개는 해당 작업에 주어진 권한을 따른다.
