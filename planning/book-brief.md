# 집필 기획

- 버전: 0.3
- 갱신일: 2026-10-13
- 제목: **The Software Factory**
- 부제: **소프트웨어 팩토리와 AI 시대의 조직 설계**
- 저자: 정도현

## 책의 핵심

IDD(Intent-Driven Development)는 인간의 의도를 정책과 실행계획으로 구체화하고, 수행 결과를 증거로 검증하며, 그 피드백으로 정책과 계획을 지속적으로 개선하는 개발 접근법이다.

이 책은 개별 모델의 코드 생성 능력에서 조직이 의도를 실현하는 전체 체계로 관심을 넓힌다. 의도, 실행, 검증, 운영 관찰과 개선을 연결하는 중심 루프를 패턴 언어로 설명하고, 소프트웨어 팩토리를 그 구현 체계로 다룬다.

특정 실행 주체에 대한 의존을 줄이려면 능력 평가, 작업 분해, 지식 공급, 독립 검증, 복구와 책임 구조가 함께 필요하다. 사람과 에이전트의 역할 및 커뮤니케이션 흐름을 다시 설계할 때 리더가 결정할 사항을 제시한다.

## 구현 예제

공통 구현 예제는 로보코의 [The Software Factory Demo](https://github.com/roboco-io/software-factory-demo)다. 고정 버전의 문서·코드·공개 실행 기록을 관련 장의 판단 원리에 연결한다. 설치 튜토리얼과 조직 효과의 입증 사례로 확대하지 않는다. 장별 범위는 [구현 사례 지도](../research/cases/software-factory-demo.md)를 따른다.

## 주 독자

소프트웨어 조직의 경영진, 임원, 부서장, 개발 관리자와 팀 리더를 대상으로 한다. 기술 배경이 있는 리더와 비기술 리더를 모두 포함한다. 새로운 개발 체계를 도입하거나 기존 체계의 성과를 개선하려는 독자를 위한 책이다.

More Effective Agile의 독자 범위와 같은 수준을 지향한다. 정확한 독자 근거와 출처는 [연구 대응 지도](../research/mcconnell/chapter-map.md)에 기록한다.

## 독자가 얻을 판단 능력

- 목적과 성공 기준을 유지하며 실행 방법을 위임한다.
- 모델·에이전트·도구·환경의 조합을 실제 업무 기준으로 평가한다.
- 수행자의 완료 선언을 결과의 증거와 연결한다.
- 자동 실행의 권한, 예외 처리와 책임을 설계한다.
- 설명, 인계 대기, 맥락 손실과 재작업의 비용을 파악한다.
- 사람의 역량과 공통 생산 기반에 대한 투자를 정한다.
- 결과의 품질과 총비용을 함께 관찰하며 도입·확대·개선을 결정한다.

## 책의 형식과 근거

본문은 오래 유효한 본질과 패턴에 집중한다. 각 패턴은 상황, 문제, 상충하는 요구, 해결 구조, 적용 절차, 결과와 비용, 실패 유형 및 연결 패턴을 포함한다.

사례는 공개 문서, 저장소와 원천 발표에서 관찰할 수 있는 정보를 중심으로 정리한다. 직접 확인한 관찰, 사례 주체의 주장, 저자의 해석과 설계 제안을 구분한다. 비교 가능한 수치가 부족한 경우에는 적용 조건과 검증할 가설을 명시한다.

특정 제품의 설치와 사용법, 모델별 가격·순위와 상세 설정은 확인일과 버전을 표시한 보조 자료에 둔다. 본문의 참조 구조와 예시는 리더의 판단을 돕는 수준으로 제시한다.

## 중심 명제와 검토 범위

| 명제 | 이 책에서 다룰 범위 |
|---|---|
| 바이브 코딩은 전체 업무 자동화를 지향한다. | 최소 수행 능력을 전제로 의도·검증·복구를 체계화하여 특정 모델에 대한 의존을 줄이는 경로를 다룬다. |
| 소프트웨어 팩토리는 IDD의 구현체다. | 의도와 정책을 실제 수행 및 운영 피드백에 연결하는 생산 체계로 구체화한다. |
| 모델과 에이전트의 선별이 중요해진다. | 사람의 판단·육성·채용과 실행 능력의 평가·구매·운영을 함께 다룬다. |
| 커뮤니케이션 비용 최적화에는 조직 설계가 필요하다. | 인계·결정 대기·책임 공백이 병목인 조건에서 권한과 팀 경계를 재설계한다. |
| 설명 가능한 자동화는 개선을 돕는다. | 의도·정책·행동·판정 증거·변경 이력의 추적 가능성을 다룬다. |

이 명제의 효과와 적용 조건은 공개 관찰과 후속 검토로 구체화한다. 전망과 설계 제안을 이미 입증된 일반 법칙으로 기술하지 않는다. IDD의 기존 사용을 인정하고 이 책의 정의와 기여를 설명한다.

## 5부·20장 목차

### 1부 의도로 개발을 이끈다

1. 코드 생성에서 의도 실현으로
2. 의도를 지속적인 기준으로 만든다
3. 정책과 실행계획을 분리한다
4. 의도 실행 루프를 닫는다

### 2부 의도를 실현하는 패턴

5. 의도를 실행 계약으로 바꾼다
6. 작업을 검증 가능한 단위로 나눈다
7. 증거로 완료를 판단한다
8. 예외와 복구를 설계한다

### 3부 소프트웨어 팩토리의 구조와 운영

9. 팩토리의 책임과 경계를 정한다
10. 일에 필요한 지식을 공급한다
11. 모델과 에이전트의 능력을 평가한다
12. 자동 실행의 권한과 검증을 연결한다

### 4부 조직과 커뮤니케이션을 다시 설계한다

13. 인재와 실행 능력에 투자한다
14. 커뮤니케이션의 병목을 찾는다
15. 업무 흐름에 맞춰 권한과 팀 경계를 설계한다
16. 리더십과 학습 문화를 다시 설계한다

### 5부 증거로 도입하고 개선한다

17. 생산성과 의도 부합을 함께 측정한다
18. 증거를 확보하며 단계적으로 도입한다
19. 실패를 정책과 계획의 개선으로 연결한다
20. 자동화의 범위를 넓힌다

More Effective Agile의 주제는 각 장에 분산하여 재고찰한다. 16장은 리더십과 학습 문화에 집중하고 23장 대응은 연구 지도와 부록에서 추적한다.

## 집필 운영

기획, 원고, 패턴과 연구 기록은 이 저장소에서 관리한다. 클라이언트에서 이어지는 집필 지시를 반영하고 변경 이유와 상태를 기록한다. 장 번호를 기준으로 원고·패턴·출처의 관계를 유지한다.

본문 약 250쪽은 초기 편집 가정이다. 출판 일정과 원서 본문 대조에 사용할 판본은 아직 정하지 않았다. 이 사항은 현재 원고와 연구 작업을 진행하는 데 필요한 선행 조건은 아니다.

현재 확정 사항과 후속 안건은 [결정 기록](decisions.md), 근거와 완료 기준은 [편집 정책](editorial-policy.md)을 따른다.


## 인간의 오너십과 책임 행동

2026-10-11 후속 지시에 따라 16장을 중심으로 사람이 자동화 속에서 유지할 판단 권한·기여·학습·결과 피드백을 다룬다. 심리적 오너십·인지적 참여·책임 행동을 구분하고 13·7·9·17장에 역할별로 연결한다. 행동경제학과 조직심리학·HCI·자동화 책임 연구를 구분하며 개입 효과는 실제 업무에서 평가할 제안으로 쓴다. 5부 20장 구조와 기존 장명은 유지한다.
