# 데모 사례 갱신 실행 안내

[정책](demo-example-maintenance-policy.md)을 실행하는 [유지관리 에이전트](../.claude/agents/demo-example-maintainer.md)와 [수정 검증 에이전트](../.claude/agents/demo-example-verifier.md)를 제공한다. 모델은 호출자의 설정을 상속한다. Claude Code는 프로젝트 에이전트 정의를 사용한다. Codex 등 다른 클라이언트에서는 AGENTS.md의 안내에 따라 같은 파일을 작업 지침으로 읽고 사용 가능한 하위 에이전트에 역할을 전달한다. 이 파일만으로 모든 클라이언트에 에이전트가 자동 등록되지는 않는다.

## 호출 예시

> 데모 사례 유지관리 에이전트를 사용해 점검해줘. 모드는 점검, 범위는 책 전체, 실행 ID는 실행마다 새 값으로 정해줘. 현재 기본 브랜치의 후보 커밋을 고정하고 이전 확인 버전과 비교해줘. 원고는 수정하지 말고 보고서와 manifest를 남겨줘.

> 같은 정책으로 수정 포함 모드를 실행해줘. 데모 변경에 영향받는 본문·독자용 해설·근거 기록을 갱신하고 별도 검증 에이전트로 확인해줘. 커밋·배포는 하지 마.

명시적인 갱신 요청이면 이미 부여된 수정 권한을 다시 묻지 않는다. 일정·알림·공개는 별도 지시에 따른다.

## 반복 실행에 쓰는 자료

- `scripts/demo_examples.py`: 작성 원본 전체를 검색해 파일 해시·언급·직접 URL·간접 출처와 검토 전 상태를 JSON으로 만든다. `--run-id`와 새 `--output` 경로를 받으며 기존 결과는 덮어쓰지 않는다. 의미 검증을 수행하지 않는다.
- `research/demo-example-cases.json`: 사례 ID·장·독자용 원본·대응 근거·확인 버전·확인 범위를 연결한다.
- `research/software-factory-demo-inventory.json`: 기존 조사의 읽은 파일·버전·범위와 후속 확인 이력.
- 실행별 보고서/manifest: 이전 후보와 이번 후보의 차이, 언급별 유지·수정·미확인, 수정 전후 해시, 실제 검증과 공개 상태를 남긴다.

같은 자료가 바뀌지 않았어도 원격 후보를 확인한 사실과 전체를 재조사한 사실은 구분한다. 의미 변화가 없으면 원고·독서 revision·독자 공지를 불필요하게 생성하지 않는다.
