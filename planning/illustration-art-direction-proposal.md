# 삽화 방향 제안

작성일: 2026-10-21. 상태: 비교 샘플과 저자 선택을 위한 제안. 본문 삽입·편집 확정·배포 없음.

## 기본 방향

코발트 블루·아이보리의 절제된 평면 편집 삽화를 권한다. 현재 사이트의 남색·아이보리와 SNS 썸네일의 코발트 색을 연결한다. 인물과 추상적인 실행 모듈로 고객 문제·목표·경계·위임·관찰의 관계를 표현한다. 사진 같은 재현이나 특정 도구 화면보다 오래 유지할 수 있는 개념을 그린다. 이는 미적·편집적 제안이며 독자 효과를 시험한 결과는 아니다.

비교 샘플은 동일한 주제를 A 평면 편집 삽화, B 입체 모듈, C 펜 드로잉으로 표현한 한 장이다. imagegen으로 새로 생성했다. 외부 작가·출판물의 그림을 인용하거나 특정 작가의 화풍을 지정하지 않았다. 샘플은 대화에 표시했고 미선택 미리보기이므로 사이트 자산에 등록하지 않았다.

| 후보 | 용도와 장점 | 주의점 |
|---|---|---|
| A 평면 편집 삽화 | 본문 개념 삽화의 기본. 화면 크기가 작아져도 큰 형태와 관계 유지 | 장식적 아이콘과 획일적인 회사 소개 그림으로 흐르지 않게 실제 논점을 선택 |
| B 입체 모듈 | 부의 도입·생산 체계 전체 조망. 기존 썸네일과 연결 | 복잡한 정책·권한 관계는 원근과 가려짐 때문에 읽기 어려울 수 있음 |
| C 펜 드로잉 | 판단·협업·오너십 같은 인간의 상황 | 반복 제작 시 형태 일관성·선명도 관리 필요 |

## 삽화와 설명 도표의 역할

상황과 개념을 직관적으로 보여주는 삽화는 A를 사용하고, 단계·권한·조건·증거의 정확한 관계는 편집 가능한 SVG 설명 도표로 표현한다. 기존 정책 계층·하네스 사이클 도표를 장식 삽화로 대체하지 않는다. 그림 안에 긴 한국어 문장을 굽지 않고 웹/원고의 캡션으로 설명을 연결한다.

## 우선 적용할 주제

1. 1장: 고객 문제와 사업 성과, 비기능 요건을 만족하는 결과에서 출발하는 팩토리. 코드 생성량을 성과로 그리지 않는다.
2. 3장: 최상위 원칙을 보존하는 정책의 적용 범위. 자연언어·구조화·혼합 표현과 실제 집행을 구분한다.
3. 4장: 의도 정의·개선과 정책 기반 하네스 개선의 두 루프가 연결되는 모습.
4. 9장: 모델·에이전트·하네스의 관계와 사람의 책임. 세 개의 독립 제품처럼 배치하지 않는다. 정책의 맥락을 채우는 심층인터뷰도 후보로 둔다.
5. 12장: 권한 원복과 이미 노출된 정보의 회수가 다른 점.
6. 16장: 자동화 속에서 사람이 목표·위임·운영 결과에 책임을 가지는 모습. 개별 승인을 남기는 방식으로 책임을 묘사하지 않는다.
7. 17~19장: 사업 결과·품질·비용·대기를 함께 관찰하며 개선하거나 중단하는 모습.

우선 1·4·9장에 각 한 장을 시험 적용한 뒤 나머지에 확대한다. 모든 장에 장식용 이미지를 일괄 삽입하지 않는다.

## 제작 기준

- 장당 한 가지 핵심 질문을 표현한다. 실제 사건이 아닌 개념 설명이면 캡션에서 그 성격을 밝힌다.
- 목표는 코발트, 정책 경계는 남색, 관찰·피드백은 청록 등 의미를 일관되게 적용하되 색만으로 구분하지 않는다.
- 사람은 목표·정책·위임·결과 책임에 연결하고 허용된 실행마다 승인하는 모습으로 고정하지 않는다. 에이전트는 허용 범위 안에서 끝까지 수행할 수 있어야 한다.
- 의도 파이프라인·에이전트 전자동 개발·정책 기반 하네스 개선의 세 축을 보존한다. 하네스를 테스트 장치 하나로 축소하지 않는다.
- 샘플의 컨베이어는 비유에 불과하다. 최종본에서는 탐색·예외·운영 관찰·두 개선 루프를 필요한 범위에서 드러낸다. 샘플에는 비기능 요건·두 루프가 충분히 표현되지 않아 그대로 본문에 넣지 않는다.
- 방패·체크·차트 아이콘을 보안의 보장, 검증의 완전성, 실측 성과로 오해하게 만들지 않는다.
- 모바일 본문 폭에서 관계와 인물이 구별되는지 확인한다. 복잡한 그림은 분리한다.
- 밝고 어두운 테마에서 모두 읽을 수 있는 아이보리 그림판을 기본으로 하고, 대체 텍스트·캡션·가독성을 확인한다.
- 로보코 로고는 원본 자산을 사용한다. 생성 모델로 다시 그리지 않고, 본문 삽화마다 반복 삽입하지 않는다.
