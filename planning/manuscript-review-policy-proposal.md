## 목적과 기본 원칙

이 리뷰는 소프트웨어 조직 리더가 어떤 결정을 왜 내려야 하며, 무엇을 관찰해 그 결정을 고칠 수 있는지 읽을 수 있게 하는 작업이다. 문장이 매끄럽거나 출처가 많다는 사실만으로 장의 논증이 충분하다고 판단하지 않는다. 사실의 정확성, 제안의 유용성, 읽기의 용이성을 각각 확인하고 최종적으로 연결한다.

책 전체의 방향과 장별 역할을 먼저 검토한 뒤 내용을 수정하고 문체를 다듬는다. 핵심 주장의 근거 부족은 첫 단계부터 표시한다. 사실 대조를 뒤로 둔다는 이유로 근거가 약한 논증을 확대하지 않는다. 근거를 확보할 수 없으면 주장 축소·제안으로의 명시·삭제 중 무엇이 적절한지 판단한다.

현재 원고에는 먼저 집필한 장과 압축해서 작성한 장이 있다. 페이지 수나 문단 수를 같게 만드는 것을 목표로 삼지 않는다. 장의 결정에 필요한 논증·반론·적용 조건이 충분한지 확인하고, 부족한 부분을 보강한다. 반복된 문장과 경고를 늘려 분량을 맞추지 않는다.

## 단계별 리뷰와 완료 조건

| 단계 | 검토 단위와 질문 | 남길 결과 | 다음 단계로 갈 조건 |
|---|---|---|---|
| 1. 전체 논증 | 서문·목차·20장. 책의 정의와 약속, 각 장의 역할이 연결되는가 | 핵심 명제, 장별 결정·기여·중복·누락의 지도 | 핵심 논증의 순서와 각 장의 책임이 설명됨. 근거가 필요한 주장은 표시됨 |
| 2. 장·패턴 내용 | 문제→원리→해결 구조→근거/해석→비용/반론→관찰 기준이 이어지는가 | 위치가 특정된 내용 수정과 보강 요청 | 핵심 결정과 작동 원리, 적용하지 않을 조건을 독자가 이해할 수 있음 |
| 3. 사실·출처 | 중요한 주장과 실제 원문·버전·날짜·조건이 맞는가 | 주장 메모·출처 대장 갱신, 확인 범위·한계 | 중대한 오기·근거 없는 단정 해소. 미검증은 표시·축소·제안 처리됨 |
| 4. 독자·문체 | 비기술 리더도 판단을 설명할 수 있는가. 반복·용어·예시가 읽기를 돕는가 | 문단 단위 수정과 독자 이해의 문제 | 용어·배경·인과가 연결되고 불필요한 구현 설명과 반복이 줄어듦 |
| 5. 통합·확정 | 수정된 장·패턴·도표·인용·메타데이터가 서로 맞는가 | 수정 검증 기록과 저자 결정 | 필수 문제 해소, 구조 검사 통과, 저자가 지정 버전을 편집 확정 |

각 단계는 문제의 종류를 나누는 기본 순서다. 뒤 단계에서 정의나 핵심 근거의 문제가 발견되면 해당 단계로 돌아간다. 한 장의 사실 확인을 마쳤다고 다른 장의 같은 출처 사용도 확인한 것으로 표시하지 않는다.

## 장별 내용 검토 기준

리뷰어는 장의 중심 주장을 한 문장으로, 리더가 내려야 할 결정을 한 문장으로 적는다. 두 문장이 장의 본문에서 도출되지 않거나 서로 맞지 않으면 내용 보강 문제로 기록한다. 제목과 패턴 이름을 되풀이하는 것으로 설명을 대신하지 않는다.

검토할 것은 문제의 발생 조건, 해결 구조가 판단을 바꾸는 이유, 실제로 누가 무엇을 제공하고 결정할지, 감수할 비용과 반론, 적용하지 않을 조건, 판단을 수정할 관찰이다. 핵심 제안에 비용이나 실패 조건이 없으면 중요한 누락으로 본다. 실제 사례가 부족하다는 이유로 경험이나 수치를 만들지 않는다. 예시와 제안으로 논증할 수 있지만 그 지위와 한계를 밝혀야 한다.

패턴은 카탈로그의 이름·ID·정의를 기준으로 검토한다. 상황·문제·상충하는 힘·해결 구조·결과와 비용·실패 경계·검증·연결을 확인한다. 여러 패턴이 같은 일반 조언으로 읽힌다면 각 패턴에 고유한 문제와 구조를 다시 설명한다. 이름을 임의로 바꾸거나 맞지 않는 의미로 연결하지 않는다.

장 사이의 중복은 같은 용어의 재등장과 구분한다. 앞 장의 기준을 새 결정에 적용하는 설명은 유지할 수 있다. 같은 주장과 예시를 새로운 기여 없이 반복한다면 줄이거나 한 장에 모은다. 핵심 구분은 특히 다음 연결에서 확인한다.

- 2·3·4장: 의도의 유지, 변경 권한, 피드백 루프의 역할.
- 5·6·7·8장: 계약, 결과 단위, 수용 판정, 실패 뒤 행동.
- 9·10·11·12장: 운영 책임, 지식, 수행 적격성, 실제 권한.
- 13·14·15·16장: 역량 투자, 소통의 원인, 팀 경계, 인간의 참여 조건.
- 17·18·19·20장: 측정, 최초 도입, 변경 효과, 범위 확대.

## 사실과 제안의 검토 기준

독자의 결정을 바꾸는 주요 주장과 날짜·수치·인물·직접 인용은 원문에 대조한다. 사실·사례 주체의 보고·저자 해석·저자 제안을 분리해 기록한다. 문서나 코드의 존재, 실제 실행, 운영 효과를 같은 확인 상태로 취급하지 않는다. 업체의 보고와 블로그의 재해석도 독립적인 인과 증거로 바꾸지 않는다.

이 책의 주요 제한을 점검한다. IDD의 최초 명명·조직 확장의 최초성을 주장하지 않는다. 모델 의존을 줄이는 목표를 최소 수행 능력과 비용·속도의 차이가 사라진다는 뜻으로 쓰지 않는다. 완전 자동화에는 대상·성공 기준·정지·복구·남는 책임을 명시한다. 조직 개편은 실제 흐름과 권한의 병목을 근거로 조건부 판단한다. 활동량·자기보고 오너십·실제 책임 행동·사용자 결과를 혼동하지 않는다.

변할 수 있는 자료는 사용한 시점과 버전을 확인하고 필요한 후속 자료나 정정을 대조한다. 공개 목차만 확보한 도서는 주제 연결의 범위를 유지한다. 본문을 적법하게 읽었을 때에만 판본·장절·페이지와 구체적인 주장을 대조한다.

출처별 직접 인용·요약의 누적 사용은 기존 지침을 따른다. 자동 공백 집계나 한국어 어절 수만으로 한도 준수를 확정하지 않는다. 다른 파일에 같은 자료를 사용한 양과 원문에서 파생한 설명을 함께 검토한다. 제3자 자료에 대한 이용 허락을 저자의 자기 글 차용 허락으로 확대하지 않는다.

실제 업무에서 효과를 검증하지 않은 패턴도 조건부 제안으로 출판을 검토할 수 있다. 현장 효과의 미검증 자체를 모든 제안의 탈락 사유로 삼지 않는다. 다만 실제 효과가 입증되었다는 표현, 그 근거가 없는 성과 수치와 보편적 인과 단정은 수정해야 한다.

## 독자와 문체 검토 기준

독자 관점에서 장을 읽고 결정·이유·적용 조건·비용·다음 관찰을 자신의 말로 설명할 수 있는지 확인한다. 저자의 설명이 있어야만 이해되는 부분은 기록한다. 실제 독자에게 읽기를 요청한 적이 없다면 AI가 생성한 반응을 독자 테스트 결과로 보고하지 않는다.

한국어 문장은 짧고 직접적으로 쓰고 같은 개념에 같은 용어를 사용한다. 전문 용어는 판단에 필요한 경우 설명한다. 모든 문단을 짧게 자르는 것이 목적은 아니다. 한 문단의 논점과 다음 문단으로 이어지는 이유가 드러나야 한다. 표·목록은 비교·대응·순서에 유용할 때 사용한다.

반복된 “이 책은 제안한다”와 검증 한계의 문구는 기계적으로 늘리지 않는다. 제안과 한계의 지위가 분명하다면 일반적인 설명은 한곳에 모을 수 있다. 독자의 결정에 영향을 주는 특정 조건과 한계는 해당 본문에 유지한다. 집필 상태·검토 절차 같은 제작 정보와 독자에게 필요한 내용도 분리한다.

특정 도구의 설정과 단기 모델 순위, 구현 튜토리얼을 리더의 원칙으로 확대하지 않는다. 글이 매끄럽다는 이유로 출처와 인과의 빈틈을 가리지 않는다. 문체 리뷰가 새로운 사실이나 저자 경험을 보충하는 작업으로 바뀌어서는 안 된다.

## 리뷰 의견의 우선순위와 형식

| 우선순위 | 기준 | 처리 |
|---|---|---|
| P0 | 만들어낸 사례·인용, 중대한 사실 오류, 확인 범위를 넘긴 성과·권리 주장 | 확인·삭제·축소 등으로 해결하기 전 편집 확정 보류 |
| P1 | 중심 논증의 모순·누락, 패턴 의미 변형, 결정·작동 원리·비용·한계가 불명확 | 해당 장의 내용 수정과 검증 후 종료 |
| P2 | 이해를 막는 용어·반복·문단 연결·예시 배치·표현 | 독자·문체 단계에서 수정하거나 이유를 기록 |
| P3 | 선택 가능한 구성·문체·예시의 제안 | 저자가 채택 여부를 결정 |

위 등급은 제안한 운영 기준이며 현재 원고의 문제를 판정한 결과가 아니다. 취향 차이를 P0/P1로 올리지 않는다. 오탈자가 의미·수치·주체를 바꾸면 심각도를 높일 수 있다. 총점으로 필수 오류를 상쇄하지 않는다.

각 의견에는 의견 ID, 대상 파일과 절·문단, 검토한 Git 버전, 문제와 독자에게 미치는 영향, 근거 또는 확인이 필요한 내용, 최소 수정 방향, 우선순위를 기록한다. “더 구체적으로 써라”처럼 위치와 부족한 판단을 알 수 없는 의견은 보완한다. 필수 수정과 선택 제안을 구분하고 해결 여부를 확인할 기준을 붙인다.

검토 기록의 상태는 `열림`, `수정됨·검증 대기`, `검증 완료`, `저자 판단 대기`, `채택하지 않음·이유 기록`으로 관리할 것을 제안한다. 검토자는 수정이 의도한 문제를 해결했는지와 새 모순이 생겼는지 확인한다. 수정자가 완료라고 선언한 사실만으로 종료하지 않는다.

## 역할과 검토의 독립성

작성자는 자기 점검과 수정, 출처 기록을 담당한다. 리뷰어는 원고와 근거를 읽고 결론과 반례를 검토한다. 저자는 독자·주장·범위와 편집 확정을 결정한다. 실제 인력을 확보하지 않았다면 수행하지 않은 외부 리뷰나 저자 승인을 기록하지 않는다.

AI는 주장·중복·용어 점검과 원문 대조의 보조, 수정안 작성을 맡을 수 있다. 자료를 읽지 않고 출처를 추정하거나 작성한 대화·경험을 사실로 제시할 수 없다. 같은 AI의 자기 점검을 독립 리뷰로 표시하지 않는다. 다른 모델을 쓴 사실만으로도 독립성이 보장되지는 않는다. 별도 기준·자료·원고만으로 읽는 관점과 인간의 최종 판단을 연결한다.

실제 독자 리뷰가 가능하다면 비기술 리더와 기술 리더가 이해한 결정과 남은 질문을 기록한다. 참여자가 적은 의견은 탐색 자료로 사용하며 전체 독자를 대표하는 검증으로 표시하지 않는다.

## 실행 순서와 종료 조건

먼저 1·7·9·16·17장을 기준 장으로 검토할 것을 권한다. 각각 책의 약속, 판정, 책임 구조, 인간의 역할, 성과 측정의 중심을 담당한다. 이 장에서 리뷰 기준과 용어를 조정한 뒤 1부부터 5부 순서로 나머지를 검토하고 15개 패턴과 왕복 대조한다. 우선 검토에서 얻은 기준을 이미 검토한 장에도 다시 적용한다.

한 번의 리뷰에서는 주요 문제를 우선 제시한다. 전체 재작성보다 문제를 해결할 최소 변경부터 판단하고, 주장·정의·구조를 바꾸면 관련 원고·패턴·출처·주장 메모의 영향을 추적한다. 글자만 바꾼 경우에도 의미와 직접 인용을 훼손하지 않았는지 확인한다. 수정 라운드 수만으로 종료하지 않는다. 반복되는 쟁점은 근거와 선택지를 정리해 저자의 판단을 기다린다.

자동 검사는 JSON·링크·ID·형식과 상태 연결을 확인하는 수단이다. 검사 통과를 사실·인과·논증·독자 이해의 승인으로 취급하지 않는다. 현재 검사에 포함되지 않은 주장 위치와 표식·대장의 의미적 일치도 별도로 확인한다.

최종 확정은 지정된 버전에서 P0/P1이 해결되고 P2의 수정·보류 이유가 기록되며, 남은 미검증의 표현이 적절하고 저자가 해당 범위를 승인했을 때 기록한다. 일부 장의 확정을 전체 원고의 확정으로 확대하지 않는다. 이전 버전의 리뷰 결과를 후속 변경에 자동 적용하지 않는다.

## 상태와 기록의 운영

이 정책을 채택하면 리뷰의 진행은 별도 대장과 세션 기록에 관리하고, 원고의 집필 상태와 구분한다. `초고`, `내용 검토`, `사실 대조`, `문체·독자 검토`, `편집 확정`을 어떤 파일에 적용할지 합의한 뒤 기존 메타데이터를 갱신한다. 정책 제안만으로 현재 20장을 검토 완료 상태로 올리지 않는다.

최종 결정에는 버전·검토 범위·수행한 확인·미해결 항목·저자와 날짜를 남긴다. 기존 출처 ID와 패턴 카탈로그, 주장 메모의 연결을 유지한다. 자료를 추가로 읽었으면 출처 대장과 주장 메모도 갱신한다. 리뷰가 다음 작성자를 같은 질문으로 되돌리지 않도록 남긴다.

## 채택 전의 현재 범위

이 문서는 기존 정책을 구체화한 제안이다. 원고의 실제 내용 리뷰, 외부 사실 대조, 리뷰 대장 구현, 장 상태 변경, 커밋·푸시는 수행하지 않았다. 정책을 채택한 뒤 기준 장의 리뷰부터 시작할 수 있다.
