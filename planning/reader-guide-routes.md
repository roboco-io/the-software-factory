# 질문 기반 장 추천의 편집 기준

- 갱신: 2026-10-15. 기존 세 질문(목적·역할·깊이)을 유지하고 최신 목차·장별 추가 내용·데모 해설에 대응시킨다. 독자의 적성을 판정하는 모델이나 실험으로 검증된 최적 경로가 아니라 책의 편집 안내다.
- 구현 기준: `website/src/lib/recommendations.mjs`. 장 제목·실제 주소는 생성된 book 데이터에서 읽고, 데모 ID는 등록된 독자용 해설과 대조한다.

| 목적 | 먼저 읽을 순서 | 책 내용과 연결한 이유 |
|---|---|---|
| 전체 개념 | 1→2→3→9→19 | 세 핵심·의도·정책 계층·하네스 책임·개선 |
| 의도 정의·개선 | 1→2→3→4→5 | 결과 선택부터 의도 환류·실행 계약까지 |
| 하네스 운영·개선 | 3→9→10→11→19 | 지침·책임·지식 공급·조합 평가·지침/집행 개선 |
| 결과 품질·검증 | 5→7→8→11→12 | 계약·증거와 수용 책임·예외·평가·실제 권한 |
| 실행 권한·책임 | 3→5→9→12 | 정책과 계획의 변경 권한부터 생성/반영/배포 경계까지 |
| 보안 대응 | 18→7→12→17→19 | 조건부 도입 가설·수정 증거·긴급 위임·전체 대응·재발 방지 |
| 팀 병목·협업 | 6→14→15→9 | 작업 단위·대기 원인·팀/권한 설계·운영 책임 |
| 오너십·학습 | 7→9→13→16→17 | 남는 수용/운영 책임·역량 투자·오너십/참여/행동 구분·평가 |
| 도입·투자 | 1→9→17→18→20 | 목적·운영·전체 비용/품질·초기시험·확대 |

역할은 목적의 경로를 바꾸지 않고 강조할 장만 고른다. 플랫폼·하네스 운영자, 보안·위험 관리 책임자를 추가했다. 목적과 역할의 교집합이 없으면 강조했다고 쓰지 않는다. 원고에서 사용하는 제품 책임자는 수용 책임자의 역할 대응을 따른다.

각 장의 이유는 목적별로 다르게 쓴다. 장 전체의 일반 결정만 반복하지 않는다. 데모는 해당 관계를 실제 구현으로 이해할 때만 연결하며, 오너십·팀 협업에 직접 대응하는 구현을 만들어 붙이지 않는다. 보안 해설은 실제 보안·준법 효과를 입증한 것으로 표시하지 않는다.

깊이의 '전체' 선택은 짧은 추천부터 시작해 전체20장으로 이어지는 안내다. 추천 자체를20개로 늘리지 않는다. 기존 저장 답변6종·역할5종·깊이3종의 ID를 보존하고 신규 선택만 추가한다. 읽기 저장 키·스키마·장별revision/anchor는 바꾸지 않는다. 기존 독자는 현재 추천을 다시 계산해 보되 답변이나 읽음 표시를 잃지 않는다. 선택한 답변은 새로운 통계 필드로 전송하지 않는다.

갱신 시 목차·원고의 주제와 근거 범위를 다시 읽고, 경로 길이3~5·장 유효성·이유 누락·데모 ID·저장 호환을 검증한다. UI의 질문/결과·접근성·기록 보존도 브라우저에서 확인한다. 전체20장을 모두 추천 경로의 합집합에서 찾을 수 있는지는 누락 점검이며, 개별 경로가 전체 책의 충분한 대체라는 뜻은 아니다.
