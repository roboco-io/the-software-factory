# 데모 사례 반복 점검 — repeat-check-stable

후속 기록: 위 안정 상태 시험 종료 뒤 진행자가 주장 메모 12파일의 검증 상태·보고서 연결만 갱신했다고 알렸다. 해당 12파일 차이를 별도로 기록하고 현재84파일을 다시 고정해 연속 두 번 읽은 결과 모두 해시가 같았다. 원고·registry·sources·독서 revision은 계속 불변이며, 주장 메모 갱신은 유지관리 에이전트가 수행한 변경이 아니다. 상세 전후 해시는 JSON의 post_run_coordinator_record_reconciliation에 보존한다.

- 날짜: 2026-10-15
- 모드/범위: 점검 / 책 전체
- 목적: 최초 repeat-check에서 탐지한 진행자의 동시 원고 수정이 끝난 뒤 전체 기준을 새로 고정하고 불필요한 다시 쓰기가 없는지 시험한다.

후보와 레지스트리의 확인 버전은 모두 `5b1927f8328266070c3d0bf98bac194dc21df012`다. 같은 점검 세션에서 고정한 원격 후보를 사용했고 compare는 identical이다. **후보 동일·본문 의미 갱신 없음**으로 기존9개 사례와 발견 언급115개를 유지한다. 이번 확인에서 기존 사례의 의미 확인 수준을 올리거나 외부 원문 전체를 다시 읽지 않았다.

새 원본 목록을 별도 실행 ID로 생성했다. 원본60파일을 검색했고 장·패턴35개가 모두 포함됐다. 원고·그림·주장 메모·registry·source·독서 manifest·정책을 포함한 보호 대상84파일의 SHA-256이 전후 모두 같다. 책 HEAD도 동일하다. 유지관리 에이전트의 원고/출처/registry/revision 수정은0이다. 스캐너 발견 상태와 실행의 유지 판단은 별도 파일에서 추적한다.

스캐너 실행과 전후 해시 대조는 통과했다. 원고·웹 코드 변경이 없으므로 빌드·브라우저 검사를 다시 실행하지 않았다. 이 시험은 자기 점검이다. 데모를 실행하거나 과거 PR을 재실행하지 않았다. 예약·자동 알림·커밋·푸시·배포를 설정하거나 수행하지 않았다.
