# 장별 TL;DR 생성·갱신 검토

## 범위와 기준

저자의 요청은 독자의 빠른 읽기를 위한 장별 TL;DR과, 이를 스킬로 생성하고 중요한 본문 업데이트와 함께 갱신하는 절차다. D55로 기록했다. 본문20장을 대상으로 하며 서문·패턴·데모 해설에는 반복 요약을 추가하지 않았다.

기존20장 완독 기록과 이 대화에서 이후 작성·검토한 변경을 기초로 각 장의 중심 주장·리더 결정·관찰/경계를 대조했다. 각 요약은 기존 논증을 압축하며 외부 사례 수치나 효과·새 패턴을 추가하지 않는다. TL;DR로 원고 전체의 사실·출처 리뷰나 저자 편집 확정을 대신하지 않는다. 원고·스킬·검사 스크립트의 최종 해시는 반영 manifest에 기록한다.

## 생성 결과

- 각 장 첫 기존 절 앞에 `## TL;DR`과 핵심/결정/확인 세 항목을 추가했다. 보통200자 안팎이며 최대450자의 규칙을 적용한다. 전체 맥락과 비용·예외·근거는 본문에 남긴다.
- 초기 삽입 전후에 TL;DR을 제외한 본문의 동일성을 확인했다. 이후 병행 작업이7·10·12·19장에 Pstack/Tstack 보강을 추가하고 해당 요약/판본 기록도 갱신한 것을 확인했다. 그 변경을 보존해 다시 대조했다. 12장 요약에는 기존 장의 핵심인 SDLC 전반 보안도 함께 유지했다.
- 나머지16장의 본문은 작업 시작과 같다. 위4장의 본문 변경은 병행 보강으로 구분한다. 기존 장/절 이름·앵커·토론 단위는 유지했고 TL;DR용 안정 앵커만 추가했다. 기존 별칭도 보존한다.
- 초기20장 요약 추가의 읽기revision을 한 단계씩 증가시켰다. 병행 작업이 별도로 증가시킨4개 장의 값은 덮어쓰지 않았다. 책 버전 번호로 표시하지 않는다. 체인지 로그는 공개 예정 항목으로 묶었다.

## 자동 갱신의 구조

| 역할 | 실제 구현 | 확인 범위 |
|---|---|---|
| 의미를 읽고 요약 생성 | `skills/chapter-tldr/SKILL.md`와 작성 정책 | 에이전트가 본문을 읽고 요약/검토 이유를 생성한다. 이전 요약만 복제하지 않는다. |
| 프로젝트 자동 발견 | `.agents/skills/chapter-tldr`의 내부 연결 및 AGENTS.md 적용 규칙 | 장의 중요한 변경 작업에서 별도 요청 없이 적용하도록 연결했다. 외부 전역 스킬은 설치하지 않았다. |
| 삽입·판본 기록 | 스킬의 `scripts/tldr.py`와 `planning/chapter-tldr-manifest.json` | 본문/기존요약 예상 해시를 대조하고 배치 전체를 먼저 검사한다. 본문을 임의로 바꾸지 않는다. |
| 누락/변경 감지 | `scripts/check_project.py`, `npm run check:tldr`, 웹 build | 누락·본문/요약 판본 불일치 시 실패한다. 빌드는 모델을 호출하지 않는다. |
| 회귀 검사 | Python 도구 테스트와 브라우저 TL;DR 테스트 | 변경/수동요약/충돌·부분반영·CLI 실패,20장 표시와 읽음 상태를 확인한다. |

형식적인 문장 정리여서 요약이 그대로일 때에는 현재 본문을 검토한 이유와 판본만 갱신할 수 있다. 본문 해시 변경을 의미 변화로 단정하지 않으며, 해시만으로 의미의 충실성을 보장하지도 않는다. 요약 수정이 필요한지는 에이전트의 본문 대조가 맡는다. 스킬은 커밋·배포·일정 생성 권한을 추가하지 않는다.

## 수정 검증

| 항목 | 수용 조건 | 결과 |
|---|---|---|
| 원고 요약 | 20개 장에 짧은3항목, 근거 범위·허용 자동화/사람 판단 경계 유지 | 초기 요약 및 병행 변경4개 장의 최신 요약을 본문과 대조 |
| 보존 | 기존 본문·안정 앵커·별칭을 요약 삽입이 훼손하지 않음 | 초기 본문20개 해시/삽입 복원, 기존 앵커 전체 보존 확인 |
| 최신성 | 본문 또는 요약이 변하면 검토 필요 상태가 됨 | 실제 임시 원고/요약 변경과 CLI 실패를 테스트로 확인 |
| 충돌 | 읽은 뒤 다른 작성자가 바꾼 본문/요약을 덮어쓰지 않음 | 예상 해시 불일치 시 배치 수정 전 거부 확인 |
| 안전한 유지 | 의미 변화 없는 본문 정리에는 같은 요약을 재검토해 보존 가능 | 동일 요약 재적용과 반복 실행의 안정성 확인 |
| 독서 | 첫 요약 표시·세 항목·짧은 분량·방문만으로 읽음 처리하지 않음 | 데스크톱/모바일20장 테스트와 대표6장×2화면 확인 |

초기 브라우저 테스트가 제목과 목록을 직접 형제 요소로 가정해 실패했다. 실제 화면에는 요약이 있었고, 제목은 프레임워크의 래퍼 안에 있었다. 사용자에게 보이는 첫 목록으로 검사 대상을 고친 뒤 전체 검사에 통과했다. 제품 동작을 바꾸어 테스트를 통과시키지 않았다.

실행 결과: Python 도구8개·웹 단위37개 통과, 스킬 형식 검사 통과, Astro오류/경고/힌트0,56페이지빌드/내부링크 통과, 기존 기능과 TL;DR 브라우저35개 통과/모바일 전용 데스크톱 검사1개 제외. 병행 업데이트 후에도 최신 판본20개 검사·56페이지빌드/링크·20장×2뷰포트의 TL;DR 검사2개와 대표 화면12개를 다시 확인했다. 현재 출처는 병행 작업의 추가를 보존한156개, 본문 인용102개다. 실제 독자 이해/읽기 시간의 효과 시험이나 독립 리뷰는 아니다.

## 인계

요약과 갱신 스킬·최신성 게이트를 구현했다. 다음 본문 수정은 AGENTS.md와 스킬에 따라 해당 장을 함께 재검토한다. 현재 원고/연구의 병행 변경은 보존하며 커밋·푸시·공개 배포는 수행하지 않는다.
