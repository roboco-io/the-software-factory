# Pstack·Tstack 원리의 원고 반영과 데모 이슈 검토

## 범위와 판본

저자는 조사 결과를 원고에 반영하고 데모 적용 이슈를 생성하도록 요청했다. [조사 보고서](../../research/pstack-tstack-factory-2026-10-27.md)의 우선 적용을7·10·12·19장에 넣었다. 도구 설치·명령 튜토리얼이나 새 패턴/새 장을 추가하지 않았다.

기존 장별 TL;DR 추가 작업이 미커밋 상태였으므로 보존하고, [TL;DR 스킬](../../skills/chapter-tldr/SKILL.md)로 해당 네 장의 요약을 본문과 함께 갱신했다. 10·19장의 현재 본문을 읽고, 같은 작업 맥락에서 이미 읽은7·12장의 판본에 추가된 내용을 diff로 대조했다. 다른16개 장은 이번 요청 시작 해시와 동일함을 확인했다. 기존 안정 앵커는 보존했고, 이미 작성되어 있던20개 TL;DR 제목의 새 앵커만 등록했다. 네 장의 읽기revision만 요청 시작 값에서 한 단계 올렸다.

책의 기준 HEAD·수정 전/후 해시·요약 판본은 [반영 manifest](2026-10-27-pstack-tstack-manifest.json)에 기록한다. Pstack/Tstack은 앞선 조사의 고정 판본을 유지한다. 실제 스킬을 실행하거나 효과를 새로 검증한 것은 아니다.

| 장 | 중심 주장 | 리더의 결정 |
|---|---|---|
| 7 | 완료·지적·실행·수용의 증거는 다르며 검증 절차도 실행해 확인해야 한다. | 확인 범위·독립 판정·반복 한도와 증거를 정한다. |
| 10 | 현재 업무에 맞는 자료와 검증 자산의 유효 범위를 유지해야 한다. | 소유·갱신·제품 수정 권한과 회귀 분류를 정한다. |

## 데모 적용 이슈

[이슈 #127](https://github.com/roboco-io/the-software-factory-demo/issues/127)을 생성했다. [작성한 본문](../demo-pstack-tstack-adoption-issue.md)과 실제 GitHub 본문이 일치하고 OPEN 상태임을 확인했다. 접수 자동화가 붙인 라벨은 `factory:triaged`, `type:feature`이며 실행 승인 라벨은 없다. 실행 승인 명령이나 수동 워크플로 요청을 보내지 않았다.

현재 데모의 기준은 `b925518f535b49f3383b23db52cc66e8139ce042`다. README·gate.ts·CI·포럼 사용자 여정 E2E, 기존 기획#79 본문을 직접 읽었다(S156). 기존 테스트·판정기를 재사용하는 설계이며 기능 부재를 전수 입증한 것은 아니다. 기존 본문에 쓰는 데모 판본과 과거 실행 근거는 바꾸지 않았다.

이슈는 #79에 연결된 설계·조정용 기획이다. 초기 신뢰 기반은 외부의 신뢰된 실행자가 단계별 PR로 구축하도록 권고했다. 검증 지도/실행, 자산 유지관리, 증거/반영 연결, 제한된 리뷰·대기, 운영 관찰로 나누어 완료 증거와 금지/미확인 경계를 적었다. 병합을 사업 목표 달성으로 세지 않고, 기존 보호 규칙을 약화하거나 현재 자동 역할이 자기 기준을 바꾸도록 요청하지 않는다. 데모 구현 자체는 수행하지 않았다.

## 확인 결과와 인계

- `chapter-tldr status/check`: 20개 장의 현재 본문/요약 판본 일치. 이번 변경은 네 장만 갱신했다. 해시 검사가 의미·정확성을 자동 승인하는 것은 아니다.
- 구조: 20장·15패턴·156출처, JSON/로컬 링크 통과.
- `npm --prefix website run check`: 오류/경고/힌트0.
- `npm --prefix website run build`: TL;DR 검사, 56페이지/인용102개, 내부 링크/앵커 통과.
- TL;DR 도구 단위 검사6개 통과.
- [화면 기록](2026-10-27-pstack-tstack-browser.json): 네 장×데스크톱/모바일8회에서 새 설명·요약3항목·출처·절/토론 링크·가로 넘침 부재 확인. 모바일 요약 화면도 확인했다.
- 기존 다른16장/앵커/타 작업의 요약 추가·워크플로·스킬 변경을 보존했다. 새 요약 앵커의 등록과 네 장의 의미 변경을 구분한다.

중요한 원고 보강은 체인지 로그의 공개 예정에 묶었다. 책의 커밋·푸시·배포는 요청받지 않아 수행하지 않았다. 외부에서 수행한 것은 명시적으로 요청받은 이슈 생성과 확인뿐이다.
