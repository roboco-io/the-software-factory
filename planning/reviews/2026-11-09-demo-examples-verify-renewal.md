# 리뉴얼 데모 사례 수정 검증

## 최종 상태와 범위

기록한 수정 판본의 별도 AI 검증을 완료했다. 열린 P0/P1/P2는 없다. 유지관리자가 작성한9개 해설·관련10장 수정 문단/TL;DR·서문/웹·도표·출처/판본을 고정 후보 `1a8d3f3a0edbeb0cba6f03b8658a08ee8127ef4a`의 원문 캐시와 대조했다. 아래 초기 의견과 수정 이력을 보존하며, 마지막 ‘최종 판정’이 최신 결과다. [해시·읽은 범위·의견](2026-11-09-demo-examples-verify-renewal.json)에 판본을 기록했다.

데모 사례 유지관리 정책·수정 검증자 정의·용어집을 적용했다. 작성자와 다른 AI 에이전트의 검증이며 독립 인간 리뷰나 저자 편집 확정이 아니다. 데모 서비스·로그인·에이전트·병합·테스트·워크플로를 실행하지 않았다.

## 확인한 주요 관계

9개 해설의 다음 설명은 읽은 코드 범위와 일치한다.

- 웹훅의 서명·운영자 ID·등록 저장소·열린 이슈와 중복 접수 조건. 외부 요구사항을 지침 변경의 허가로 취급하지 않는 프롬프트 구성.
- 제어 평면과 구현/리뷰 샌드박스, 실제 키의 출구 주입, 신뢰하지 않는 변경 목록의 검사와 제어 평면 게시.
- 기본 브랜치의 정책을 커밋으로 고정해 읽는 경로, 현재 PR 헤드·유효 리뷰·체크의 앱/성공 결과·운영자 승인과 병합의 연결.
- PR 이전 실패와 PR 이후 사람 이관, 단순 승인 대기와 종료 상태, 중지 요청과 이미 시도한 병합의 구분.
- 공급사 예산과 예약을 고려한 구현/리뷰 조합, 단일 공급사 시 낮은 위험에만 다른 모델 리뷰를 허용하는 분기.
- D1 실행/사건/사용량과 토큰·고정 단가의 추정 비용, 미측정·단가 미확인과 사용자 효과/실제 청구의 구분.
- 기존 자기개선 리허설을 Conveyor의 과거 판본으로 분리하고 새 플랫폼의 자동 자기개선 완료로 확대하지 않는 설명.

신규 코드 링크 25개 파일이 고정 후보의 취득한 원문 캐시에 대응하고, 9개 해설의 로컬 복귀 링크 대상이 존재함을 확인했다. 이 확인은 전체 외부 링크의 응답이나 기능 동작 시험을 뜻하지 않는다.

## 의견

### RV-D01 / P2 / 검증 완료(아래 초기 의견과 수정 이력)

- 위치/판본: `manuscript/demo/agent-selection.md`, ‘선언·배정·호출을 함께 읽는다’의 두 번째 문단. 초기 SHA-256은 JSON 참조.
- 독자 영향: ‘높은 위험이나 위험을 확인하지 못한 변경은 다른 리뷰 조합을 기다린다’에 앞 문장의 ‘한 공급사만 남은 경우’를 반복하면 무조건 대기로 오해할 여지가 줄어든다. 또한 ‘대기·소진·미확인은 같은 결과가 아니다’는 실제 실행 결과가 모두 구분된다는 인상을 줄 수 있다.
- 근거/확인 범위: `budget.ts`의 `chooseReviewer`는 다른 공급사에 예산이 있으면 일반 선택을 진행하고, `assessBudget`은 `spentUsd:null`을 상한 도달 상태로 취급한다. 정적 코드 대조다.
- 최소 수정: 한 공급사만 남은 경우의 높은/미확인 위험 대기를 명시하고, 소진·미확인을 0 지출이나 사용 가능 상태로 취급하지 않는다는 범위로 좁힌다.
- 수용 조건: 실제 선택·보류·미확인 처리와 문장의 조건이 일치함을 재대조한다.

## 판정과 인계

초기 해설9개 대조에서 열린 P0/P1은 없었고, P2 한 건을 작성자에게 전달했다. 새 플랫폼에 이전 판본의 Apache-2.0 이용 조건을 승계하지 않도록 출처 등록 시 확인하도록 알렸다. 해설 자체에서 그 오기는 발견하지 않았다.

초기 단계에서 남았던 본문·출처·도표·링크·revision·TL;DR과 최종 해시는 후속 통지 뒤 아래와 같이 대조했다. 이전 리뷰 완료를 새 파일에 자동 적용하지 않았다.

## 전체 내용 1차 대조 추가

관련10장의 변경 사례 문단·TL;DR, 서문/소개/추천, 새 출처9개, 사례 registry·역사 inventory/claims 구분, 코드/포럼 URL, 도표2개를 대조했다. 기존156개 출처의 확인일·코드 판본과15개 패턴 원고는 보존됐다. 옛20개 출처의 canonical URL은 동일 이전 판본의 Conveyor 위치로 옮겨졌으며 원래URL·이전안내 이력이 기록돼 있다.

RV-D01은 한 공급사 조건·미확인 지출의 처리 표현이 수정돼 수용 조건을 충족했다. 추가로 지적한 RV-D02(P2: 선택 함수의 unknown tier 분기와 전체 경로의 정책 미확인 처리를 구분)는 T2/T3 엔진 대기와 보류·사람 확인의 설명을 나눠 해소했다. RV-D03(P2:7장의 사례 제목)은 새 리뷰/실행 증거 구분에 맞춘 H2로 변경됐고, 기존 s06과 옛 제목 alias를 보존했다. 세 의견 모두 현재 변경 범위에서 검증 완료다.

D-2의 마지막 수정도 확인했다. 실행 중 모델 요청은 출구를 거쳐 샌드박스로 돌아오고, 변경 보고는 별도 경로로 제어 평면의 검사·게시로 간다. 출구가 게시 전 고정 단계인 것처럼 읽히는 관계를 해소했고 SVG 설명/목록과 일치한다.

구조 검사20장/15패턴/165출처와 TL;DR20개 최신성 검사 통과. 기존 안정 앵커 전부·관련20개 reading revision 각1증가를 대조했다. 신규 출처는 정적 확인 한계와 이전Apache-2.0 미승계를 명시한다. 내용1차 대조에서 열린 P0/P1/P2는 없었다. 최종 파일 해시 및 부모의 처리 manifest는 아래 최종 판정에서 확정했다.

## 최종 판정 — 기록한 판본의 수정 검증 완료

유지관리자의 최종 고정 통지 뒤 [처리 매니페스트](2026-11-09-demo-examples-renewal-manifest.json)와 실제51개 변경 파일의 SHA-256을 독립적으로 계산해 모두 일치함을 확인했다. 원본61개 파일157개 언급의 위치 집합이 처리 결정157개와 정확히 대응하고, 현재61개 파일106개 언급 목록의 파일 해시도 현재 원본과 일치한다. 새S157~S165의 판본과 근거 파일 그룹도 같은 고정 후보를 따른다.

사례 registry는 현재 판본/확인일과 이전 registry를 분리했다. 역사 inventory/claims의 옛 확인일·판본은 Conveyor 기록으로 유지하고 현재 근거를 `renewal_20261109`에 따로 연결했다. 이전156개 출처의 날짜·판본은 유지됐으며 옛 링크 이동은 원래URL과 확인 범위를 기록했다.15개 패턴 원고는 바뀌지 않았다. 관련20개 페이지의 reading revision은 각각1 증가했고 모든 기존 안정 앵커가 보존됐다. 7장의 바뀐 제목도 기존s06과 옛 제목 별칭을 유지한다.

정적 의미 대조 범위에서 열린 P0/P1/P2는 없다. RV-D01·RV-D02·RV-D03은 수정 문장·제목/앵커·근거를 재대조해 모두 검증 완료다. source/정책 판본의 한계, 현재 구현과 미래 계획, 이전 자기개선과 새 관찰 기반, 병합과 배포/사용자 성과를 구분한 상태를 확인했다. D-2의 최종 모델 호출/응답 루프와 변경 보고의 게시 경로도 Outbound 응답 반환과 상태 기계의 변경 수집/게시 관계에 부합한다.

검증자가 실행한 프로젝트 구조 검사와20개 TL;DR 최신성 검사는 통과했다. 유지관리자는 Python10개·웹단위37개·Astro0진단·56페이지빌드/링크·전체E2E35통과/의도된제외1개·최종도표검사4개를 보고했고, 해당 결과는 부모의 실행 범위로 인계한다. 이 검증자가 그 브라우저/플랫폼 시험을 별도로 재실행했다는 뜻은 아니다.

최종 해시·읽은 범위·닫힌 의견·남은 제한은 같은 접두사의 JSON에 있다. 실제 확인 내용은9해설과 관련10장의 수정 문단/TL;DR·서문·웹·도표·출처/판본 관리 및 관련 코드 정의/함수다. 전체 책의 모든 문장이나 새 플랫폼의 전체170개 파일을 통독·실행한 검증으로 확대하지 않는다. 실제 데모·OAuth·에이전트·병합·배포·운영 효과·보안 효과·과거 로그의 재현은 미수행이며, 독립 인간 리뷰·독자 이해 효과·저자 편집 확정은 여전히 별개다. 이번 검증에서 원고/공유 파일 수정·커밋·푸시·배포는 하지 않았다.
