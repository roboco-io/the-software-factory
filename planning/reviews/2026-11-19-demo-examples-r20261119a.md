## 1. 결론

변경 영향이 있는 사례 7개(요청, 정책과 수용 경계, 복구, 권한, 에이전트 선택, 개선, 소개)를 후보 판본 기준으로 고쳤다. 증거·지표 2개 사례는 후보와 대조했으나 설명이 달라지지 않아 11월 9일 판본의 확인을 유지했다. 도표 2개와 3·7·17·19장은 변경하지 않았다. 1장·서문·README·웹 소개·안내 페이지는 확인 기준일 문구만 정리했다.

이번 변경의 핵심은 세 가지다. 첫째, 플랫폼이 이전에 확인하지 못했다고 적던 DNS 유출과 인젝션 문구를 플랫폼이 직접 시험해 기록했으므로, 그 기록을 플랫폼의 보고로 귀속해 설명하고 시험하지 않은 범위를 함께 적었다. 둘째, 플랫폼에 팩토리 전체 중지·배포 없는 예산 한도 변경·게스트 요청 심사·Dependabot 병합 점검이 추가되었다. 앞의 둘은 배포되어 동작하는 기능이고 뒤의 둘은 후보 판본에서 동작하지 않는다. 셋째, 플랫폼의 `docs/status.md`가 실서비스 확인 여부의 유일한 원본이 되었다. 해설은 그 구분을 따르고, 플랫폼의 확인을 이 책이 재현한 것처럼 쓰지 않았다.

## 3. 변경한 사례와 이유

- 소개(`demo/index.md`, 1장·서문·README·웹 소개): 후보에 추가된 세 경로의 확인 상태를 한 문단으로 구분하고, 페이지별 확인 기준일을 안내했다. 그림 D-1의 설명에 도표가 운영자 경로만 그렸다는 범위를 더했다.
- 요청(`demo/request.md`, 5장): 게스트 심사 경로가 코드에 있고 접수가 닫혀 있으며 실제 요청 처리 기록이 없다는 점만 적었다. 근거 표를 후보 링크로 옮기고 심사 흐름·판정 형식·접수 설정·상태 문서를 더했다.
- 정책과 수용 경계(`demo/policy-and-gate.md`, 12장): 판정 함수와 별개인 Dependabot 점검 경로를 비활성 상태로 적었다. 병합 판정이 모든 병합 경로를 설명하지 않는다는 점을 한계에 더했다.
- 복구(`demo/recovery.md`, 8장): 팩토리 전체 중지의 순서·범위·재시작 조건, 플랫폼이 확인한 것과 시험으로만 확인한 것을 적었다.
- 권한(`demo/execution-authority.md`, 9장): DNS 실험과 인젝션 시험의 조건·결과·하지 않은 시험·루트 실행을 플랫폼 기록으로 서술했다. 실험은 별도 실험용 서비스에서 에이전트 컨테이너와 같은 네트워크 구성으로 했다는 점, 모델 하나·문구당 1회라 비율이 아니라는 점을 유지했다.
- 에이전트 선택(`demo/agent-selection.md`, 11장): 대체 구현 도구, 배포 없는 한도 변경, 플랫폼이 확인한 전환 경로와 남은 확인 항목을 적었다.
- 개선(`demo/improvement.md`): 확인 상태의 원본이 `docs/status.md`로 옮겨 간 구조를 반영하고, 원인을 알 수 없었던 실패 사례와 플랫폼이 스스로 적은 미측정 항목(성공률·리뷰 차단율, 실행 20건)을 더했다. 후보에서도 자기개선 루프는 찾지 못했다.

옛 고정 링크는 모든 7개 페이지에서 후보 커밋으로 옮겼다. 후보에서 다시 읽지 않은 파일(`prompt.ts`, `policy.ts`, `github-pulls.ts` 등 12개)은 전후 blob SHA가 같음을 확인해 같은 내용으로 취급했다. 한 주장 안에서 두 판본을 섞지 않았다. 해설 9개의 저장소 링크 48개(후보 링크 40개, 11-09 고정 링크 8개)가 각 링크의 커밋에 실제로 존재함을 `git cat-file`로 확인했다. 증거·지표 해설은 11-09 고정 링크를 유지한다.

## 4. 유지한 사례와 근거

- 결과를 판단하는 증거(`demo/evidence.md`, 7장): 인용 파일 중 `review-prompt.ts`·`review-verdict.ts`는 동일하고 `review-command.ts`는 Anthropic 모델 리뷰용 호환 설정과 실패 로그만, `decision.ts`는 함수 내보내기와 체크 집계 함수만 추가되었다. 페이지 설명이 여전히 맞아 11-09 판본을 유지했다. S160에는 후속 대조 기록만 남겼다.

- 3·7·17·19장, 패턴, 도표 2개(`demo-flow.svg`, `demo-authority-boundary.svg`): 도표는 운영자 경로와 권한 경계를 그리며 후보에서도 맞다. 게스트·전체 중지·Dependabot은 그리지 않았고 그 범위를 소개의 그림 설명과 도표 목록에 적었다.
- 19장의 PR #47·#48 역사 사례와 옛 Conveyor 링크: 당시 판본의 사례로 보존했다.

## 7. 확인하지 못한 항목

- 플랫폼의 실서비스 확인(2026-11-06~11-14)은 플랫폼 소유자의 보고다. 이 실행은 서비스를 호출하거나 재현하지 않았다. 소개 페이지·포털·Conveyor의 HTTP 응답도 이번에는 다시 확인하지 않았다(11-09 확인만 유지).

## 8. 저자 판단 항목

1. **게스트 요청 심사를 어디까지 설명할지.** 현재는 요청 해설에 한 절, 5장에 한 문장, 소개에 한 문단을 두고 ‘코드가 있고 접수가 닫혀 있으며 실제 요청 처리 기록이 없다’까지만 적었다. 플랫폼의 7단계가 진행 중이라 구조가 바뀔 수 있다. 선택지는 (a) 현재 수준 유지, (b) 실제 게스트 요청으로 확인될 때까지 해설 절을 줄이고 소개의 한 문장만 둔다, (c) 확인 뒤 심사 판정 구조를 시작 판단 자동화 논의와 연결해 확장한다. 이 보고서의 권고는 (a)이며, 시작 판단 자동화의 사례로 쓰려면 (c)의 조건(실제 요청 처리)이 먼저 필요하다.
2. **헤더 ‘데모 대시보드’ 링크 대상.** `BookHeader.astro` 7행은 factory-test-app 대시보드를, 서문·소개는 conveyor 대시보드를 가리킨다. 2026-11-10 세션이 4개 대상을 확정했고 플랫폼도 factory-test-app를 공개 시험 저장소로 계속 쓴다(`docs/status.md`). 책이 데모로 소개하는 대상은 conveyor다. 통일하려면 저자가 대상을 정해야 하며 이번 실행에서는 바꾸지 않았다.
3. **Dependabot 점검을 12장·정책 해설에 계속 둘지.** 비활성 경로를 명시해 ‘병합 판정 함수만으로 모든 병합 경로를 설명하지 못한다’는 한계의 예로 썼다. 활성화 계획이 없다면 비중을 줄일 수 있다.
4. **플랫폼 기록의 인용 강도.** DNS·인젝션 시험을 플랫폼의 보고로 귀속해 서술했다. 책이 이를 더 전면에 둘지, 한 단락으로 줄일지는 장의 논증 균형에 달렸다.
5. **서문·1장의 reading revision.** 기준일 문구만 바뀌어 올리지 않았다. 기준일 변경도 독자 알림 대상으로 보려면 두 revision을 올린다.
6. **공개.** CHANGELOG의 ‘공개 예정’ 항목은 공개 확인 뒤 실제 날짜로 옮긴다. 이번 실행은 공개 권한이 없다.
