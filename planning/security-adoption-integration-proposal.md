# 보안 압력과 도입 동기의 반영 제안

- 2026-10-15 사용자 제공 로컬 글을 읽고 기존12·17·18·20장과 대조했다. S107은 저자의 조건부 전망·설계 제안으로 기록했다. 외부 사고·법규·통계의 원문 대조는 아직 하지 않았다. 공개 후보 URL의 게시 여부도 확인하지 않았다.
- 결론: 새 장보다18장을 중심으로 적용하고12·17·19장에 담당 논점을 나눈다. 이미 보유한 권한·검증·개선 설명을 반복하지 않는다.

| 장 | 반영할 논점 |
|---|---|
| 18장 | 보안 압력을 도입 동기로 제시하되, 발견 이후 분류·수정·검증·배포 대기가 병목인지 확인하고 제한된 보안 수정으로 시험한다. |
| 12장 | 긴급성이 권한·직무 분리의 완화를 정당화하지 않는다. 정상 경로의 사전 위임, 준비된 증거, 예외 판단과 당번·연락 경로를 연결한다. 팩토리 자체의 공격면도 다룬다. |
| 17장 | 발견/접수→분류→수정→검증→배포의 시간과 대기, 미해결 고위험 항목의 노출 기간, 회귀·재개방·사람 검토 부담을 같은 조건에서 비교한다. 지표는 책의 제안이다. |
| 19장 | 보안 실패를 지침·검사로 바꾸고 실제 검출·회귀·오탐을 확인한다. 상위 원칙을 완화하지 않는다. |

핵심 문안 제안: 보안 요구는 자동화를 제한하는 조건인 동시에 발견에서 안전한 수정·배포까지의 시간을 줄이는 체계에 투자할 동기가 될 수 있다. 그 대기가 주요 병목인 조직에서는 팩토리의 도입 가치가 커질 수 있다. 자동화를 늘렸다는 사실 대신 실제 대응 시간·품질·위험·전체 비용으로 판단한다.

사고 나열과 변하기 쉬운 수치·제품·규정 설명은 본문 중심에 두지 않는다. 필요한 외부 관측만 1차 자료로 재확인해 사용하며 보고와 조치 기한을 구분한다. 확인되지 않은 AI 공격 관여나 보안 동기 도입 확산을 사실로 쓰지 않는다. 코드 수정은 노출 키의 폐기·재발급이나 전체 사고 대응을 대체하지 않는다.

이번 산출물은 반영 제안과 근거 성격 기록이다. 본문·웹·revision·체인지 로그는 수정하지 않았고 커밋·푸시·배포도 하지 않았다.

## 2026-10-15 후속 반영

저자가 제안을 승인해18장 중심과12·17·19장의 연결을 반영했다. S108(NIST 공식 서지 초록),S109(Anthropic 공식 보고),S110(GitHub 공식 발표)의 필요한 부분을 직접 확인했다. 최초 제안의 원문 미대조 상태는 당시 이력으로 보존한다. 현재 확인 범위와 미채택 항목은 [근거 메모](../research/security-adoption-evidence.md), 수정 검증은 [보고서](reviews/2026-10-15-security-adoption.md)에서 추적한다. 커밋·푸시·배포는 별도다.
