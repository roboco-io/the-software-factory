# 데모 사례 해설·갱신 정책 작성

- 요청: 코드 링크 없이 이해되는 본문 사례, 복잡한 관계의 독자용 해설, 에이전트로 반복 수행 가능한 갱신 절차를 우선 정책으로 정한다.
- 산출물: [정책](../demo-example-maintenance-policy.md), AGENTS.md 진입 링크, STATUS.md 진행 기록.
- 확인: 기존 집필 기획·목차·패턴 카탈로그·리뷰 정책·근거 규칙·데모 통합 계획·사례 지도·조사 목록의 구조를 확인했다. 데모 원격 최신 버전이나 코드 동작은 조사·실행하지 않았다.
- 범위: 정책 작성만 수행했다. 원고·해설 페이지·에이전트·예약 실행·출처 대장·독서 revision·체인지 로그는 변경하지 않았다. 커밋·푸시·배포도 하지 않았다.
- 다음: 정책 검토 뒤 실행 에이전트/스킬을 연결하고 책 전체 언급을 목록화해 최초 점검·수정을 수행한다.

- 정책 작성 검증: `python3 scripts/check_project.py` 통과(20장·15패턴·97출처), `git diff --check` 통과. 정책의 역할·근거 버전·갱신·미확인 처리·실행 권한·완료 조건을 자기 점검했다. 공개 웹 변경이 없어 웹 빌드·브라우저 검사는 실행하지 않았다.
