# The Software Factory Demo — 장별 구현 사례 지도

## 기준과 읽는 방법

예제는 [roboco-io/the-software-factory-demo](https://github.com/roboco-io/the-software-factory-demo)다. 2026-10-13 확인한 공개 main의 기준 커밋은 `25a73b9c342ef380f96ff0d705df9b7ef33dd82c`이며 커밋 시점은 2026-10-12T22:58:02Z다. 파일 목록 339개 항목은 잘림 없이 받았고 그중 관련 파일 25개를 기록했다. 전체 저장소를 통독한 것은 아니다. 파일별 blob SHA·고정 URL·읽은 범위는 [조사 목록](../software-factory-demo-inventory.json), 서지와 제한은 [출처 대장](../sources.json)에 있다.

프로젝트의 소개는 저자 측 설명, 코드의 조건은 정적 확인, PR의 결과는 공개 기록 확인으로 구분한다. 이번 조사에서 로컬 설치·테스트·AI 실행·서비스 조작·배포·워크플로 재실행은 하지 않았다. main의 CI·deploy 성공 표시는 확인했으나 그것만으로 책의 모든 주장이나 생산성 효과를 검증한 것으로 쓰지 않는다.

## 공개 실행 기록의 확인 범위

PR #47의 head는 `7f65b26d7d48a4dc9e49e461bb7e4886ad3f03dd`이고 eval job은 `114724977130`이다. PR #48의 head는 `60ef31c9e9db979fe290e3bd0493d8a6bb5e1b71`이며 lint가 검사한 임시 병합 커밋은 `4dc986c9c8f06bf891e7d77720eb36463c16313d`, job은 `114726765443`이다. 두 로그의 판정 위치를 직접 읽었다.[S68] 임시 병합 커밋이 존재한다고 PR #48이 실제 병합되었다고 표시하지 않는다.

프로젝트 README가 설명하는 리허설의 인위적 조건을 유지했다. 자료만으로 모든 리뷰·승인 과정이나 각 실행의 인과관계를 재구성하지 않는다. 19장의 사례는 이 두 job에서 확인한 범위를 넘겨 전체 개선 체계의 효과로 일반화하지 않는다.

## 비용·한계와 차용 범위

이 책의 예제로 사용하기에 적합한 것은 조건·권한·증거가 연결되는 구조다. 조직 규모·역할 배치·소비자 환경이 바뀌면 책임과 관찰 비용도 달라진다. README에 기록된 실행 환경·판정 조작·사람 기여자의 승인 경계 같은 제한은 해당 논점을 설명할 때 함께 남겼다. 임계값과 등급은 이 구현의 선택이며 표준이나 권장 수치로 복제하지 않았다.

고정 README의 라이선스 절과 LICENSE에서 자체 코드·문서·설정의 Apache-2.0 표시를 확인했다. 외부 테스트와 의존성에는 별도 조건이 있으므로 이 허락을 제3자 자료로 확대하지 않는다. 이번 원고는 짧은 구조 설명과 출처 링크를 쓰며 코드·원문·스크린샷·로그 전체를 복제하지 않는다. 출처별 기본 인용·요약 한도 안에서 누적 사용을 점검하고, 설명의 확장이 필요하면 허락 범위와 이용 조건을 별도로 다시 확인한다.

## 남은 확인

업무별 장기 효과, 사람 판단의 질, 전체 비용, 원서 본문과의 대조는 이 조사로 완료되지 않는다. 실시간 대시보드의 모든 렌더링과 데이터 품질, 실제 저장소 권한 전부도 확인하지 않았다. 원고의 제안을 운영에 적용하려면 해당 조직의 기준으로 시험해야 한다.
