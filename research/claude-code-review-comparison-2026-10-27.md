# Claude Code Review 공식 문서와 책의 논조 비교

## 범위와 결론

2026년 10월 27일 확인. 대상은 관리형 **Code Review 서비스**와 연결된 맞춤 지침·PR 결과·비용 문서다. 로컬 `/code-review`, Ultrareview, Claude Code 팀의 내부 운영 전체를 같은 제품으로 취급하지 않는다. 제품을 실행하거나 효과를 재현하지 않았다.

책에서는 7장의 리뷰/독립성·수용 설명, 11장의 조합 비교, 12장의 실행/반영 권한, 17장의 지표 해석, 19장의 리뷰 개선 절과 P07을 대조했다. 장별 중심 주장·리더의 결정은 아래와 같다.

| 대상 | 책의 중심 주장 | 리더의 결정 |
|---|---|---|
| 7장·P07 | 지적·완료 보고·실행 증거·수용은 다른 판단이며 독립성은 경로의 성질이다. | 어떤 증거와 독립 경로로 결과를 수용할지 정한다. |
| 11장 | 실제 업무에서 실행 조합의 적격성과 전체 부담을 평가한다. | 통제 가능한 조합과 비교 조건을 고른다. |
| 12장 | 분석·변경·수용·배포 권한을 나누되 허용 범위는 완전 자동화할 수 있다. | 정책을 실제 반영 권한과 연결한다. |
| 17장 | 지표의 분모·누락·기간을 읽어야 한다. | 무엇을 성과와 미확인 상태로 셀지 정한다. |
| 19장 | 리뷰 기준도 실패·정상 사례와 운영 신호로 평가한다. | 어느 지침·집행·평가를 어떤 근거로 바꿀지 정한다. |

**결론은 방향의 정합성이다.** 제품은 결함 탐지 계층이며, 책은 그 계층을 포함해 고객 결과와 안전한 자동 실행을 연결할 운영 체계를 제안한다. 적용 범위의 차이를 논리적 충돌이나 책의 우월성으로 해석하지 않는다.

## 공식 문서에서 직접 확인한 사실

| 출처 | 확인한 제품 설명 |
|---|---|
| [S139 개요](https://code.claude.com/docs/en/code-review) | 여러 에이전트의 탐색·지적 확인·중복 정리/중요도 분류를 거쳐 PR에 결과를 남긴다. 코드는 읽고 대조하며 빌드·실행하지 않는다. 서비스 자체는 PR을 승인하거나 차단하지 않는다. 지적이 없다고 결함·보안 문제가 없다는 보장은 아니다. |
| [S140 맞춤 지침](https://code.claude.com/docs/en/code-review-customize) | 프로젝트 지침과 리뷰 전용 지침을 구분한다. REVIEW.md는 PR이 바꾸는 사본이 아니라 기준/기본 브랜치에서 읽으며, 보호 상태에 따라 적용 범위가 달라진다. 서비스와 로컬 명령이 읽는 파일도 다르다. |
| [S141 PR 결과](https://code.claude.com/docs/en/code-review-pull-requests) | 자체 체크는 실패로 끝나지 않지만 별도 CI가 결과를 해석해 병합 조건으로 사용할 수 있다. 결과 누락을 지적 0건으로 처리하지 않도록 안내한다. 수정·반박은 다음 리뷰의 판단에 연결된다. |
| [S142 비용](https://code.claude.com/docs/en/code-review-costs) | 깊이와 변경/주변 코드의 복잡도, 실행 빈도에 따라 비용이 달라진다. 예산 등의 조건으로 리뷰가 생략될 수 있다. |

위 내용은 문서가 설명하는 기능·제약이다. 실제 탐지율·오탐률·독립성·생산성 향상에 대한 독립 검증 자료가 아니다. 발표일은 확인하지 못했으므로 확인일을 사용한다.

## 책의 해석과 대조

### 1. 리뷰와 수용을 분리하는 방향은 일치한다

책은 리뷰 지적을 현재 변경에 대한 근거로 검토한 뒤 수용 조건과 연결하도록 제안한다. 결함을 찾는 역할과 반영할 권한이 같지 않다는 해석은 위 제품의 역할 분리와 정합적이다. 책 12장은 이미 공개 리뷰 제품과 팀 내부 자동 병합을 구분하고 있다.

중요한 점은 **‘서비스가 병합을 결정하지 않는다’에서 ‘반드시 사람이 매번 승인해야 한다’를 도출할 수 없다는 것**이다. 조직은 서비스의 출력을 다른 증거와 함께 정책에 연결할 수 있다. 반대로 리뷰 완료 표시만으로 자동 병합이 허용된다고 읽어서도 안 된다. 이 구분은 책의 완전 자동화 기준을 유지할 이유다.

### 2. 지적 확인과 실행 검증을 더 명확하게 나눌 필요가 있다

책 7장의 S112는 Claude Code 팀이 설명한 다층 운영에 관한 블로그 출처다. 이 비교에서 읽은 S139는 관리형 제품의 문서다. 두 자료가 다루는 대상을 혼합하면 독자가 ‘리뷰가 검증했다’를 실제 실행 증거까지 확보했다는 말로 읽을 수 있다.

이 책의 해석으로는 다음 세 질문을 나누는 편이 정확하다. 코드상 결함 주장이 타당한가, 실제 지정 조건에서 무엇이 관측됐는가, 그 근거가 현재 수용 범위를 충족하는가. 정적 검토는 첫 질문에 기여한다. 제품이 테스트를 실행하지 않는다는 이유로 정적 검토가 무가치한 것은 아니며, 테스트 통과가 모든 결함의 부재를 보장하는 것도 아니다.

### 3. 다중 에이전트와 검증의 독립성은 같은 개념이 아니다

책 P07은 기준의 근거·검증 자료·판정 권한을 구분한다. 이 기준에 따르면 참여한 에이전트의 수는 독립성을 평가할 출발 정보일 뿐이다. 업무별 오류 상관관계, 놓친 실패와 정상 결과의 오탐을 따로 관찰해야 한다. 공식 기능 설명을 독립성이나 효과가 입증됐다는 근거로 확대하지 않는 현재 책의 제한은 유지할 만하다.

### 4. 정책 파일과 정책의 집행을 연결하는 구체 사례가 된다

책 3·9·12장의 관점에서는 리뷰 지침의 내용만큼 어느 판본을 신뢰하고 누가 이를 바꿀 수 있는지가 중요하다. 리뷰 대상 변경이 자신에게 적용할 평가 조건도 임의로 낮출 수 있으면 위임 경계가 약해질 수 있기 때문이다.

이 제품 사례에서 책이 얻을 수 있는 해석은 지침의 신뢰 위치와 적용 여부를 관측해야 한다는 것이다. 다만 이 책의 최상위 원칙·정책 계층 전체가 제품 파일 구조에 구현됐다고 쓰지는 않는다. 지시를 파일로 저장했다는 사실을 실제 권한 제한의 보장으로 바꾸지도 않는다.

### 5. 비용·생략·반복 리뷰도 판정 경로의 상태다

책 17장의 원리대로라면 ‘문제 없음’과 ‘리뷰 미수행/결과 미확인’을 집계에서 나누어야 한다. 생략을 통과로 세면 자동화 지표는 좋아져도 확인 범위는 줄 수 있다. 비용은 도구 요금 외에도 지적 판독·불필요한 수정·대기까지 포함해 평가한다.

19장의 관점에서는 지적의 수정·반박이 기준의 개선으로 이어지는지 확인한다. 운영자가 오탐과 누락을 평가할 이유는 있지만, 제품이 곧 조직의 정책을 스스로 학습·개선한다고 해석하지는 않는다. 11장의 조합 선별도 통제 가능한 서비스 설정·지침·외부 검증 환경을 평가하는 방식으로 적용할 수 있다. 모델을 직접 고르는 설정이 없는 서비스에 모델 교체 실험을 그대로 요구할 필요는 없다.

## 보강 후보와 수용 조건

모두 편집 제안이며 아직 본문을 수정하지 않았다. 이번 검토는 P0/P1 결함을 판정하는 전체 사실 리뷰가 아니다.

| ID·우선순위·상태 | 위치 | 독자 영향·최소 보강 | 수용 조건 |
|---|---|---|---|
| CR01·P2·제안 | 7장 「리뷰를 수행 중의 검사와 수용 판단으로 나눈다」 | S112 내부 운영과 S139 제품을 구분하고 지적 검증/실행 증거/수용 판정을 짧게 대조 | 특정 제품이 빌드·실행한 것으로 오독할 표현이 없고 각 근거 범위가 맞음 |
| CR02·P2·제안 | 12장 「변경의 위험과 현재 증거를 병합 판단에 연결한다」 | 제품 체크 완료와 정책상 병합 허용의 차이, 결과 누락의 보류 경로를 설명 | 사람의 매회 승인 의무를 새로 만들지 않으며 결과 없음이 자동 통과가 되지 않음 |
| CR03·P3·선택 | 3·9·12장 정책 설명 중 한 곳 | 지침의 내용·신뢰 판본·집행·적용 확인을 한 사례로 연결 | 제품의 파일 구조를 책의 전체 정책 계층과 동일시하지 않음 |
| CR04·P3·선택 | 17·19장 | 미수행을 분모에서 숨기지 않는 예와 반박/재검토의 운영 비용을 연결 | 생략과 지적 0건을 구분하고 효과 수치·자가 개선 기능을 창작하지 않음 |

새 장을 만들거나 기존 자동화 논조를 뒤집을 필요는 없다. 우선 7·12장의 경계 설명을 보완하고 나머지는 기존 정책·지표·개선 설명에 짧게 연결하는 편이 중복을 줄인다.

## 판본과 검토 한계

책 HEAD·관련 파일 SHA-256은 [주장 메모](claims/claude-code-review-comparison.json)에 기록했다. 새 공식 문서 S139~S142는 출처 대장에 별도로 등록해 기존 S112를 덮어쓰지 않았다. 직접 인용 없이 필요한 기능 관계만 요약했으며, 출처별 반복 사용은 서지·확인 범위와 위 사실 표를 중심으로 제한한다.

원고·읽기 revision·독자 체인지 로그는 변경하지 않았다. 별도의 제품 설치·PR 리뷰 요청·워크플로 실행·병합 또는 배포도 수행하지 않았다. 기존 화살표 수정 작업은 그대로 보존했다.

후속: 저자의 원고 반영 요청에 따라 CR01·CR02를7·12장에 반영했다. [반영 검토](../planning/reviews/2026-10-27-code-review-integration.md)에서 수정 범위·판본·검증 결과를 확인할 수 있다. 위 비교 단계의 당시 범위는 보존한다.
