# 공개자료의 근거 규칙

| 성격 | 무엇을 말할 수 있는가 | 무엇을 추가로 확인할 것인가 |
|---|---|---|
| 직접 확인한 관찰 | 공개 문서·코드·PR에 해당 내용이 존재한다. | 고정 커밋, 날짜와 주변 맥락 |
| 사례 주체의 보고 | 사례 주체가 효과나 과정을 이렇게 설명한다. | 측정 조건, 대조군과 독립 확인 |
| 원문의 설명 예시 | 원문이 개념을 설명하기 위해 사용했다. | 실제 사건·성과 사례로 바꾸지 않기 |
| 저자 해석 | 관찰에서 이 책이 도출한 의미다. | 다른 설명, 반례와 적용 조건 |
| 설계 제안 | 이 책이 권하는 원리·패턴이다. | 검증할 조건과 실패 경계 |
| 검증 결과 | 정해진 조건에서 관찰한 결과다. | 재현 조건, 비교 범위와 일반화 한계 |

확인 상태는 미확인, 관련 부분 확인, 코드 구조 확인, 실행 확인, 운영 성과 확인을 별도로 기록한다. 문서를 읽은 것만으로 실제 동작이나 생산성 효과를 검증했다고 하지 않는다.

업체의 엔지니어링 글은 유용한 1차 자료지만 독립적인 인과 검증은 아니다. 공개 저장소의 PR 수, 코드량과 자동화 지침도 고객 가치의 직접 지표로 간주하지 않는다.

출처마다 제목, 작성 주체, URL, 발표일(확인된 경우), 확인일, 확인 범위와 한계를 남긴다. 원고의 [Sxx] 표식은 sources.json에 연결한다. 원서 본문을 확보하지 않은 맥코넬 대응은 목차 주제 재고찰로 표시한다.

출처별 직접 인용과 요약 한도는 AGENTS.md를 따른다. 원문을 대량 번역하거나 조사 폴더에 복제하지 않는다.
