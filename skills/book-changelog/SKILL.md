# 독자용 체인지 로그

먼저 [작성 정책](references/policy.md)을 읽고 적용한다. 결과는 독자가 다시 읽거나 판단·사용을 바꿀 이유가 있는 변경만 담는다.

## 수행

1. 현재 작업 디렉터리에서 책 저장소를 찾고 AGENTS.md, CHANGELOG.md, STATUS.md와 요청 범위를 확인한다. 사용자가 지정한 전후 원고·diff·기준 커밋·공개 상태를 우선하고, 없으면 Git 상태와 관련 변경 기록에서 범위를 특정한다. 관계없는 파일 전체를 조사하거나 과거 완료 기록을 현재 변경으로 재작성하지 않는다.
2. 관련 장·패턴·웹 동작의 실제 전후를 읽는다. 각 후보에 대해 독자 영향, 원고 위치, 근거, 공개 여부를 구분한다. 중요한지 판단하기 위한 짧은 메모는 내부 검토용이며 공개 로그에 그대로 붙이지 않는다.
3. 정책으로 포함·제외를 결정한다. 작은 오타라도 사실·권한·책임을 바꾸면 포함할 수 있고, 큰 리팩터링도 독자 영향이 없으면 제외한다. 중요한 변경이 없으면 CHANGELOG.md를 그대로 두고 그 이유만 보고한다.
4. 같은 영향의 변경은 묶고 날짜·짧은 설명·관련 장 링크로 쓴다. 공개를 확인하지 못한 변경을 오늘 공개한 것으로 쓰지 않는다. 필요한 경우 ‘공개 예정’에 두고 공개 확인 후 실제 날짜로 옮긴다. 이미 공개한 이력을 덮어쓰거나 책 버전을 새로 만들지 않는다.
5. 실제 원고와 설명·링크·정정의 의미·공개 상태를 다시 대조한다. 책의 CHANGELOG.md는 웹 /changelog/로 생성된다. 웹 반영까지 요청받았다면 저장소의 빌드·링크 검사를 따른다. 독자에게 중요한 변경과 집필·배포 작업 기록을 구분해 STATUS.md 또는 기존 세션 기록에 검토 범위를 남긴다.

## 범위

검토만 요청받았다면 수정안을 제시한다. 작성·갱신 요청에는 정책에 맞는 파일 수정을 수행한다. 체인지 로그 작성 자체가 원고 개편·GitHub Release 생성·커밋·푸시·배포 권한을 추가하지 않는다. 기존 사용자 승인이 해당 행동과 범위를 포함하면 그 범위에서 진행한다.

간결하게 완료 내용을 보고하고, 제외한 사소한 변경은 종류와 이유만 묶어서 설명한다. 테스트·빌드 통과는 내용의 정확성이나 독자 효과의 증명이 아니다. 보관용 스킬 경로는 skills/book-changelog이며 다른 환경에서도 이 파일과 references/policy.md를 함께 사용한다.
