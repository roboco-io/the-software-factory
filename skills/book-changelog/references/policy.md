# 독자용 체인지 로그 작성 정책

『The Software Factory』의 변경 기록은 독자가 무엇을 다시 읽고, 이해나 판단·사용 방법을 어떻게 고쳐야 하는지 알려준다. 커밋의 목록이나 집필자의 작업 일지를 대신하지 않는다.

## 기록할지 결정하는 기준

다음 질문에 구체적으로 답할 수 있을 때만 기록한다.

> 이 변경을 모르는 독자가 책을 이해하거나 적용하거나 읽는 과정에서 중요한 차이를 놓치는가?

답은 “몇 줄 바뀌었다”가 아니라 독자에게 달라진 설명·판단·행동이어야 한다. 변경량이나 파일 수로 중요도를 판단하지 않는다.

### 기록할 변경

- 중심 주장·정의·적용 조건·책임·권한·실패 경계가 달라져 독자가 판단을 고쳐야 하는 수정.
- 이전 설명의 사실 오류·오해를 바로잡는 정정. 한 단어나 숫자 수정이어도 의미가 바뀌면 포함한다.
- 중요한 장·패턴·사례의 추가나 실질적 보강, 읽는 순서나 찾는 위치가 달라지는 구성 변경.
- 증거의 철회·출처 교체·확인 범위의 축소로 기존 결론을 다시 봐야 하는 변경.
- 독자의 접근·재사용 조건에 영향을 주는 라이선스나 공개 범위의 변경.
- 추천·검색·읽기 기록 등 독서 기능의 중요한 추가, 오류·기록 손실·접근 장애를 해결한 수정. 독자가 알아야 할 복구·재설정·제한이 있으면 명시한다.
- 첫 공개처럼 독자가 새로 사용할 수 있게 된 내용과 기능의 간결한 안내.

### 보통 기록하지 않을 변경

- 의미가 같은 오탈자·띄어쓰기·조사·문장 다듬기, 중복 문장의 단순 삭제.
- 장식·여백·색상·정렬 등 이해나 접근에 실질 영향이 없는 화면 조정.
- 커밋·푸시·빌드·테스트 수행, 내부 기획·리뷰·스킬·의존성·CI 설정의 유지보수.
- 정상 리다이렉트가 있는 URL 이름 변경이나 내부 파일 이동처럼 독자의 행동이 달라지지 않는 정리.
- 계획·조사 후보·작업 중인 수정. 완료하지 않은 것을 완료한 변경으로 쓰지 않는다.

보통 제외하는 유형이라도 실제로 의미·권리·접근·기록에 중요한 영향이 있으면 포함한다. 예를 들어 ‘허용한다’를 ‘허용하지 않는다’로 고친 것은 한 단어여도 중요한 정정이다. 라이브러리 업데이트가 읽기 기록 손실을 해결했다면 라이브러리 버전 대신 복구된 동작과 독자의 조치를 적는다.

## 글의 형태

- 공개 체인지 로그에는 책의 버전 번호를 사용하지 않는다. 공개 확인일의 `YYYY-MM-DD`를 기준으로 최신 항목부터 정리한다.
- 독자용 원본은 CHANGELOG.md, 웹 경로는 /changelog/다. 날짜와 링크로 원고 위치를 찾을 수 있게 한다.
- 아직 공개되지 않은 중요한 변경은 필요할 때 맨 위의 ‘공개 예정’으로 구분한다. 구현 완료·검증·실제 공개는 다른 상태다. 공개가 확인된 뒤 실제 공개일로 옮긴다. 불명확하면 날짜를 꾸미지 않고 확인 범위를 보고한다.
- 항목마다 ‘무엇이 달라졌는지’와 ‘독자에게 어떤 의미가 있는지’를 짧게 연결한다. 필요한 장·절 링크를 붙이고 행동이 필요할 때만 조치를 적는다.
- 동일한 독자 영향의 여러 커밋은 하나로 묶는다. 같은 날의 독립적인 중요한 변경은 함께 기록하되 오래전 변경의 날짜를 오늘로 바꾸지 않는다.
- 보통 한 날짜에 2~5개 항목이면 충분하지만 분량을 맞추려고 항목을 만들거나 중요한 정정을 누락하지 않는다. 해당 변경이 없으면 파일을 수정하지 않는 것이 정상 결과다.
- 공개 항목에 커밋 SHA·파일 목록·테스트 통과 수·내부 작업 경과·자기평가를 나열하지 않는다. 근거는 비공개가 보장되지 않는 저장소의 작업 기록에 필요한 범위만 남긴다.

## 정확성과 이력

실제 원고·웹 동작·승인된 정책의 전후 차이에서 작성한다. 저자의 의도·시행한 변경·관찰한 효과를 구분한다. 배포했다고 이해도나 생산성이 좋아졌다고 쓰지 않는다.

이미 공개한 중요한 항목은 임의로 지우지 않는다. 틀린 설명을 정정할 때는 기존 판단을 어떻게 바로잡았는지 새 기록으로 연결한다. 최초 릴리즈 노트를 날짜 중심 로그로 전환하는 경우 기존의 실제 공개일과 중요한 내용을 보존하고 제목·버전 표현만 정리할 수 있다.

기록 대상이 논쟁적이면 ‘포함 근거: 독자가 놓칠 차이’를 한 문장으로 먼저 써 본다. 근거가 약하면 제외한다. 중대한 사실·권리·책임 변경인데 의미를 확인할 자료가 부족하면 부족한 근거를 명시하고 필요한 확인만 요청한다.
