# 장별 TL;DR

이 저장소의 장별 핵심 요약을 만든다. [작성·갱신 정책](references/policy.md)을 읽고 적용한다. 원본은 각 장 첫머리의 `## TL;DR`이며 웹에서 따로 요약하지 않는다.

## 생성·갱신

1. 저장소의 AGENTS.md·STATUS.md와 변경 범위를 확인한다. `python3 skills/chapter-tldr/scripts/tldr.py status --root .`로 누락·본문 변경·요약 변경 상태를 찾는다. 특정 장은 `--chapters 7 12`처럼 고른다.
2. 해당 장의 **본문**을 읽는다. 같은 작업 맥락에서 이미 완독한 판본을 재사용한다면 그 판본과 현재 파일의 차이를 직접 확인한다. 앞선 TL;DR·기획안·장 제목만으로 새 요약을 확정하지 않는다. 출처·주장 메모는 사실 지위나 적용 조건이 불분명할 때 확인한다.
3. 본문에서 핵심 주장·리더의 결정·관찰/경계를 세 항목으로 압축한다. 기존 `이 장에서 내릴 결정` 문장을 복제하기보다 논증과 조건을 설명한다. 중요한 주장·권한·예외·판정 기준이 바뀌면 TL;DR도 갱신한다. 본문에 없는 설명이 필요하면 요약에 먼저 만들지 말고 수정 권한 안에서 본문을 보완한다.
4. 아래 형태의 임시 JSON을 작성한다. 해시는 status의 값을 그대로 사용한다. `expected_tldr_sha256`는 처음 생성할 때 null이다. 날짜는 현재 사용자/세션의 날짜를 사용한다.

```json
{"updates":[{"chapter":7,"expected_body_sha256":"본문 해시","expected_tldr_sha256":null,"bullets":["**핵심:** 본문의 핵심 주장.","**결정:** 리더가 정할 것과 조건.","**확인:** 판단을 고칠 관찰이나 중요한 경계."],"reason":"본문을 대조해 이 세 항목을 선택한 이유"}]}
```

5. `python3 skills/chapter-tldr/scripts/tldr.py apply --root . --input /tmp/chapter-tldr-update.json --date YYYY-MM-DD`로 반영한다. 본문·기존 요약이 읽은 뒤 바뀌었다면 도구가 거부한다. 다시 읽고 병합한다. 이 도구는 **요약을 생각해 쓰는 모델을 대신하지 않는다**. 스킬을 사용하는 에이전트가 생성하고 도구가 안전한 삽입·판본 기록을 맡는다.
6. 내용이 같은 문장 정리라서 요약 변경이 필요 없으면 기존 세 항목을 그대로 제출하고 `reason`에 이유를 쓴다. 본문이 달라졌다는 이유만으로 요약 문구를 억지로 바꾸지 않는다. 기존 요약을 읽지 않고 해시만 승인하지 않는다.
7. 원고와 TL;DR을 다시 대조한다. 장별 읽기 revision은 이번 요청 시작 값을 기준으로, 의미 있는 본문/TL;DR 변경에 한 번만 증가시킨다. 이미 본문 수정에서 올렸다면 중복 증가하지 않는다. 새 TL;DR 제목은 기존 안정 앵커를 보존해 `npm --prefix website run content -- --update-anchors`로 등록한다.
8. `python3 scripts/check_project.py`와 웹 빌드/링크를 확인한다. 새 표나 배치·읽기 위치에 영향을 줬다면 해당 화면도 확인한다. STATUS와 필요한 주장/변경 기록을 남긴다. 독자에게 중요한 추가는 book-changelog 정책에 따라 공개 예정으로 묶는다.

본문 수정 작업에서는 요약 갱신을 마지막 검증 전에 함께 수행한다. `check_project.py`와 `npm run build`가 판본 불일치를 차단한다. 빌드가 외부 모델을 호출하거나 내용을 임의로 다시 쓰지는 않는다. 예약 자동화·설치·커밋·푸시·배포 권한은 이 스킬에 포함하지 않는다.
