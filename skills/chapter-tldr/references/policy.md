# TL;DR 작성·갱신 정책

## 독자에게 줄 것

- 대상은 본문20장이다. 서문·패턴 카드·데모 해설은 별도 요청 없이 같은 구조로 늘리지 않는다.
- 장의 첫 기존 H2 앞에 `## TL;DR`을 둔다. 편집 상태 뒤에 배치하고 기존 본문·앵커는 보존한다.
- 장의 주요 내용을 **10개 미만(1~9개)의 불릿**으로 정리한다. 보통5~8개가 적당하지만 장의 내용에 따라 달라질 수 있다. 항목 수를 맞추려고 같은 뜻을 나누거나 정보를 만들지 않는다.
- 각 항목은 장에서 설명한 개념·관계·작동 원리·조건·예외 중 한 요점을 독립적으로 전달한다. 목차 제목만 나열하거나 독자에게 내리는 행동 지시만으로 채우지 않는다. 장의 전개 순서나 이해에 필요한 순서를 따른다.
- ‘핵심/주장·결정·확인’의 고정 분류와 머리말을 사용하지 않는다. 필요한 결정·책임·관찰 조건은 해당 내용에 자연스럽게 포함한다. 보통 항목당 한두 문장, 합계400~800자 안팎으로 쓰고 최대1200자를 넘지 않는다. 분량은 상한이지 목표가 아니다.
- 새로운 사실·수치·사례·출처·패턴 이름을 만들지 않는다. 외부 사례의 성과보다 이 장에서 독자가 가져갈 판단을 우선한다.
- 주장 유형·조건·불확실성을 보존한다. 저자의 설계 제안을 입증된 법칙으로, 제한된 근거를 보장으로 바꾸지 않는다.
- 허용 범위의 완전 자동화, 사람에게 유보한 판단, 미확인 상태를 필요한 장에서 구분한다. 책임을 개별 승인 의무로 바꾸거나 모델 합의를 보안/정확성의 보장으로 쓰지 않는다.
- 표·코드·설치법·내부 버전/해시·작성 경과는 독자 요약에 넣지 않는다. 필요하면 본문으로 독자를 안내한다.

## 갱신할 때

- 주장·정의·리더의 결정·권한·책임·예외·수용 기준·중요 근거/한계·주요 사례 해석이 바뀌면 스킬로 본문과 함께 요약을 재검토한다.
- 같은 뜻의 오탈자·조사·문장 정리·단순 링크 정리는 요약이 그대로일 수 있다. 이 경우도 본문을 대조한 이유와 현재 판본을 기록한다.
- TL;DR 자체의 수동 수정도 현재 본문과 대조해 기록한다. 이전 본문의 기록을 새 본문에 승계하지 않는다.
- `planning/chapter-tldr-manifest.json`은 본문/TL;DR 해시와 검토 이유를 저장한다. 최신성 검사는 **검토 누락을 찾는 장치**이며 요약의 의미·정확성·저자 승인을 자동으로 보장하지 않는다.
- 이력 기록으로 검토 사실과 공개 여부를 구분한다. 내용이 그대로면 독자 읽기 revision/체인지 로그를 불필요하게 늘리지 않는다.
