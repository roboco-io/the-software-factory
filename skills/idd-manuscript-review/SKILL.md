# IDD 원고 리뷰

소프트웨어 조직 리더가 내릴 결정, 그 이유와 비용, 판단을 고칠 관찰을 검토한다. 원고의 집필 상태와 리뷰 결과, 저자의 편집 확정을 구분한다.

## 범위와 기준

1. 사용자가 지정한 원고 경로에서 프로젝트 루트를 찾는다. 작업 트리와 HEAD를 확인하고 기존 변경을 보존한다. 미커밋 원고는 파일 SHA-256도 기록한다. Git이 없으면 파일 해시로 검토 버전을 특정한다.
2. 프로젝트의 `AGENTS.md`, `STATUS.md`, `planning/book-brief.md`, `outline/toc.md`, `pattern_catalog.json`을 읽는다. 리뷰 정책은 `planning/manuscript-review-policy-proposal.md`, 편집 기준은 `planning/editorial-policy.md`, 근거 기준은 `research/evidence-policy.md`에서 확인한다. 사용자가 지정한 후속 정책이 있으면 그것을 적용한다. 정책이 없으면 [휴대용 기준](references/policy-baseline.md)을 사용하고 적용 기준을 보고한다.
3. 대상 원고, 관련 패턴, `research/claims/`의 주장 메모와 `research/sources.json` 해당 항목을 읽는다. 일부만 읽었다면 그 범위를 명시한다. 자료 부재는 확인 제한으로 기록하고 가능한 검토를 계속한다.

기본 모드는 리뷰다. 원고·카탈로그·집필 메타데이터를 수정하는 권한으로 확대하지 않는다. 사용자가 수정을 요청하면 최소 변경과 영향 파일을 수정한다. 수정 검증 요청이면 기존 의견과 실제 변경을 대조한다. 보고서 저장 요청은 원고 수정 요청과 구분한다. 커밋·게시·편집 확정은 각각의 사용자 지시를 따른다.

대상이 명확하면 바로 진행한다. 전체 리뷰는 1·7·9·16·17장을 먼저 검토한 뒤 부별로 패턴과 대조한다. 특정 장·단계 요청은 그 범위를 따른다. 불명확한 범위가 결론을 실질적으로 바꾸면 비동기 질문을 하고 독립적인 확인을 계속한다.

## 검토 수행

전체 논증 → 장·패턴 내용 → 사실·출처 → 독자·문체 → 통합 검증 순서로 진행한다. 핵심 근거 부족은 발견한 단계에서 바로 표시한다. 뒤 단계의 문제가 앞 논증을 바꾸면 돌아가 검토한다.

- 장별로 중심 주장과 리더의 결정을 각각 한 문장으로 적는다. 문제 조건, 해결의 작동 원리, 행위자·권한, 비용·반론, 적용하지 않을 조건, 관찰 기준을 확인한다. 패턴의 ID·이름·정의는 카탈로그와 대조한다.
- 사실·사례 주체의 보고·저자 해석·제안을 나눈다. 중요한 주장·수치·날짜·직접 인용은 원문과 대조한다. 연결된 조사 도구를 우선 사용하며 Exa를 요청받으면 Exa를 사용한다. 검색 요약은 원문 확인을 대신하지 않는다. 접근 실패와 원문 일부 확인을 통독으로 보고하지 않는다.
- 문서·코드 존재, 실행, 운영 효과를 구분한다. 변할 수 있는 내용은 시점·버전·후속 정정을 확인한다. 출처별 누적 사용을 다른 원고와 조사 파일까지 확인한다. 새 자료를 읽으면 출처 대장과 주장 메모에 확인 범위·한계를 기록한다. 원고 수정 권한이 없으면 근거 기록만 갱신하고 본문 변경은 제안한다.
- 한국어의 용어·문단 연결·반복을 검토한다. 분량 균등화, 경험·성과 수치의 창작, AI 반응을 실제 독자 시험으로 표시하는 작업은 하지 않는다.

## 의견과 검증 결과

항상 [보고 양식](references/report-format.md)을 사용한다. 핵심 결함을 먼저 제시하고 선택 제안을 구분한다. 의견마다 위치·버전·독자 영향·근거·최소 수정·완료 증거를 갖춘다. 문제를 찾지 못했다면 의견을 만들어내지 않고 확인 범위와 남은 불확실성을 기록한다.

수정 선언은 `수정됨·검증 대기`다. 수정된 원고와 근거를 실제 읽고 수용 조건 및 관련 정의·인용·장 연결을 확인한 뒤 `검증 완료`로 바꾼다. 이전 버전 검증을 새 변경에 자동 적용하지 않는다. 해결하지 않은 논쟁은 근거와 선택지를 정리해 `저자 판단 대기`로 남긴다.

`python3 scripts/check_project.py`가 있으면 구조 검증에 사용하고, 수정했다면 `git diff --check`도 실행한다. 구조 검사 통과는 사실·인과·논증·독자 이해의 승인과 구분한다. AI 자기 점검과 다른 모델 사용만으로 독립 리뷰를 주장하지 않는다.

종료 시 수행 범위, 미확인 자료, P0/P1 잔여 문제, P2 처리와 다음 작업을 기록한다. 편집 확정은 지정 버전의 필수 문제 해소와 실제 저자 승인 증거가 있을 때만 기록한다. 일부 검토를 전체 책 검토로 확대하지 않는다. 저장소 작업에서는 `STATUS.md`와 세션 기록에 실제 수행을 남기되 집필 상태를 임의로 올리지 않는다.
