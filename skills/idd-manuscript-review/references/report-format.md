# 리뷰 보고 양식

보고서는 아래 항목을 순서대로 포함한다. 짧은 리뷰도 필수 필드를 유지한다. 빈 의견 목록은 허용한다.

## 범위

- 적용 정책·검토 단계·대상 파일/절
- 검토 버전: HEAD 및 미커밋 대상의 SHA-256; Git 부재 시 파일 해시
- 실제 읽은 원고·자료 범위, 미확인 자료와 접근 제한
- 장별 중심 주장 / 리더의 결정 각 한 문장

## 의견

| 필드 | 필수 내용 |
|---|---|
| ID / 우선순위 / 상태 | 예: R001 / P0 / 열림 |
| 위치 / 버전 | 파일·절·문단 또는 확인한 행; 대상 버전 |
| 문제 / 독자 영향 | 어떤 판단이 왜 잘못되거나 불가능해지는가 |
| 근거 / 확인 수준 | 주장 유형, 출처 ID·원문 위치·실제 확인 범위, 미확인 사항 |
| 최소 수정 | 근거 확보·주장 축소·제안 표시·삭제 또는 구조 보강 |
| 수용 조건 | 수정 후 무엇을 읽거나 확인해야 해당 문제를 닫을 수 있는가 |

예시(합성 시험 자료): R001 / P0 / 열림. v2의 두 번째 문장은 기능 설명 S01을 조직 생산성 효과의 입증으로 확대한다. 독자가 투자 효과를 보장받는다고 오해할 수 있다. 제공된 S01은 설정 기능만 확인했다. 효과 단정을 삭제하거나 미검증으로 좁힌다. 수용 조건은 수정 문장과 관련 주장 메모에서 효과 입증 단정이 해소되고 출처 범위가 일치하는 것이다.

## 판정과 인계

구조 검사 결과, 해결·잔여 의견, 검토 완료 단계와 미완료 단계, 다음 작업을 적는다. 편집 확정과 저자 승인 증거는 별도로 적는다. 승인이 없으면 승인 미확인으로 남긴다. 실제 원고를 검토하지 않은 시험·양식 작성은 원고 리뷰 완료로 기록하지 않는다.
